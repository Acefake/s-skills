# wukong-init Implementation Plan

> **执行方式：** 按已确认方式使用 executing-plans；已授权子代理执行时使用 subagent-driven-development。仅要求写计划不授权实现。步骤使用复选框。

**Goal:** 新增显式技能 `wukong-init`，按固定顺序编排 `setup-s-instructions` 与 `setup-s-models`，一次完成全局提示词和模型配置。

**Tech Stack:** Markdown 技能文件、Python 3.10+ 校验脚本（仓库 `.venv`）。

**验证与授权：** 第 2 档（新增技能加文档，不涉及可执行逻辑）。TDD 不适用：没有新代码，替代检查是现有的 `test_skill_resources`、`test_trigger_cases`、`test_host_support`、`test_version_docs` 与 `check_marketplace.py`。未授权提交：完成后保留工作区修改并报告。版本号与 `plugin-versions.lock.json` 不动，发布另行决定。

## Global Constraints

- `description` 沿用仓库格式：「触发词」+ 一句中文说明 + `Use when ...` 英文句。

# 一键初始化 s

只在用户明确调用本技能或要求一次配好 s 时运行。它只负责顺序和汇总，具体做法都在两个现有技能里，不在这里重复。

## 1. 识别宿主

按 [setup-s-instructions](../setup-s-instructions/SKILL.md) 第 1 节识别 Codex、Claude Code、Cursor 或 WorkBuddy；无法确定才询问。只处理当前宿主。

## 2. 检查全局提示词

用 [global_instructions.py](../setup-s-instructions/scripts/global_instructions.py) 对当前宿主做只读检查，不带 `--apply`，以返回的 `status` 为准。退出码 2 是检查结果，不是失败。

## 3. 按状态处理提示词

- `configured`：说明已是最新，不写入，进入第 4 步。
- `missing` 或 `outdated`：说明将改的位置和备份方式，用户明确同意后，按 setup-s-instructions 第 2 节加 `--apply` 写入，再检查一次，预期 `configured`。
- Cursor 需要核验时：按 setup-s-instructions 的 Cursor 分支处理，没有真实 User Rules 编辑能力就交付 block 并标记“尚未配置”，不算完成。
- 用户拒绝或跳过：记下“提示词未配置”，仍可继续第 4 步。

## 4. 配置模型

加载 [setup-s-models](../setup-s-models/SKILL.md)，从它的“一次一问”开始，原样执行，包括第 3 步展示完整 18 行、第 4 步确认后才写入。不在这里替它预选预算或模型。

## 5. 汇总

分别跑 setup-s-instructions 的只读检查和 setup-s-models 的 `check`，报告：

- 宿主与当前插件版本。
- 提示词：状态、位置、是否修改、备份位置。
- 模型：配置文件路径、预算、是否通过 `check`。
- 未完成项，以及提示“新会话才会加载全局规则和模型配置”。

## 失败与中断
