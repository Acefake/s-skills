wukong 技能全景：从一句话开始，路由怎么选技能，34 个技能各干什么

一、从开始到路由：一句话怎么走到技能

① 开始

用户任务、目标和已有授权。

↓
② 当前宿主与全局规则

先看可用技能与项目约定；不混读其他项目。

↓
③ 直接匹配或 wukong-router

有明确对口技能就直接加载；拿不准才走路由。

④ 判断（从上往下）

1. 点名了哪个技能？
→ 直接加载点名技能

2. 是明确的小改动吗？
→ 跳过方案与计划

3. 新功能或改行为？
→ 需求、计划、执行、评审

4. 跨模块、大迁移或并行？
→ 用 executing-plans

点名技能

明确要用哪个：直接加载，不绕完整开发流程。

→
读取点名技能

显式技能只在点名或已授权工作流中使用。

→
按技能步骤处理

理解、文档、审查等各有对应能力。

→
适用验证

按任务类型与风险选择，不重复跑同一检查。

→
交付结果

说明产物、证据和实际限制。

小改动 · 快路

意图明确，1–2 个文件，不改接口、结构或依赖。

→
跳过方案与计划

只加载真正对口的技能。

→
直接处理

修 bug 仍先定位根因；界面沿用既有规范。

→
相称验证

文案等第 0 档只看 diff；代码按验证分档。

→
代码自审；按风险评审

检查差异与调用方；先自审；跨模块、改接口或高风险改动再加独立只读评审。

中等任务 · 主流程

新功能、改行为或已有明确需求的多步任务。

→
brainstorming

澄清意图、目标与约束，确认设计。

→
writing-plans

拆成有文件、步骤与验收的实现计划。

→
按已确认方式执行

主任务执行；已有委派授权时才派实现者。

→
验证与双重评审

适用检查、主任务自审、独立只读评审。

→
授权后 Git 操作

commit-pr 或分支收尾；没有授权不提交推送。

复杂任务 · executing-plans

跨模块、大迁移或复杂协作：按书面计划执行。

→
executing-plans 选择做法

主会话、子代理逐任务或可审计流程，按授权选择。

→
架构与做法

实质未决时用 architect；无现成做法先定可审计流程。

→
按授权组织协作

并行群体作战与子代理各自负责明确任务。

→
记录与适用验证

长任务记录决定，检查目标实际行为。

→
评审与授权收尾

高风险改动派只读独立评审；Git 与清理仍看授权。

🆕 两个新伙伴：一个帮你说清楚，一个帮项目记住
📒 项目记录 → 🔎 prompt-sharpen 先读记录，必要时研究与澄清 → 🛠️ 领域技能执行 → ✏️ 需要时 project-memory 按 diff 同步
需求清楚就直接做；记录沿用已有位置，没有约定才用 docs/project/。check 只读，init 先确认。

二、每个技能干什么：从入口到能力

浅色实底＝可自动选用 白底虚线＝用户点名或已授权派发每张卡只列触发例子与职责摘要；点击卡片查看原始 SKILL.md，实际调用以其政策和当前授权为准。

① 🧭 入口与配置2 个

先匹配；初始化同步全局规则与子代理模型。

wukong-router自动

何时：拿不准 / 没有全局规则

作用：先直接匹配对口技能；拿不准才路由，并选择相称的验证强度。

wukong-init手点 / 授权派发

何时：/wukong-init

作用：显式初始化、检查或修复当前宿主的全局技能规则，并匹配四个子代理角色模型，写入前确认，保留用户其他配置。

② 🤝 工作模式2 个

仅点名或已授权工作流派发时使用。

架构与策略

architect手点 / 授权派发

何时：/architect / 给这个做架构

作用：写代码前勾勒类型、函数签名和模块结构，实现过程中一直参与。

长任务与记录

show-me-your-work手点 / 授权派发

何时：/show-me-your-work / 留下决定记录

作用：长时间或无人值守的工作，每个决定记一行。

③ 🛠️ 开发主流程15 个

按任务需要选用，不代表必须整列执行。

需求到执行

prompt-sharpen自动 · 新增

何时：🔎 需求太模糊 / 优化提示词

作用：需求翻译员：先读项目记录，再研究、问缺口、改写需求；已经清楚就跳过。

project-memory自动 · 新增

何时：📒 建项目档案 / 同步项目记录

作用：项目笔记本：init 先确认建档，sync 按 diff 更新，check 只读检查；沿用已有记录位置。

brainstorming自动

何时：做个新功能 / 加个接口

作用：先摸清需求、目标和约束，确认设计；明确的小改动按快路处理。

writing-plans自动

何时：写个实现计划 / 先拆步骤

作用：已有规格、要做多步任务时，先写成可执行计划。

executing-plans自动

何时：按这份计划做 / 派子智能体逐个做 / 开个 worktree / 反复检查直到通过 / /swarm 并行跑一遍

作用：把写好的计划做完：主会话或子代理逐任务执行，先隔离工作区，避免并行子代理共用文件，循环检查直到通过；点名 swarm 时按 Antigravity 原生群体协调者并行派工，其他宿主改用可用的子代理派发。

调试、测试与质量

systematic-debugging自动

何时：修 bug / 报错了

作用：先查根因再改。bug-fix 和 fix bug 也走这里。

tdd自动

何时：先写失败测试 / 补个回归测试

作用：有便宜的本地测试点就先写会失败的测试再修。路径贵或说不清就跳过。

test-strategy自动

何时：测什么 / 放在哪一层测

作用：给功能或项目定每层用什么工具、哪些不测，并写出命令。覆盖 TypeScript、React、Vue、Go、Java。

code-style自动

何时：文件放哪 / 补文档注释

作用：按模块就近放文件，遵循已有规范；交付前自审完整差异和关键调用方。

deslop自动

何时：/deslop / 提交前清一下 AI 味

作用：清这次 diff 里的代码腔：多余注释、不该有的防御、过深嵌套。文字腔用 technical-writing；只清注释时派 comment-sicko。

审查与收尾

requesting-code-review自动

何时：做完了帮我审查 / 合并前核验一下

作用：代码交付前派只读评审者核对完整差异与关键调用方，风险决定范围。

receiving-code-review自动

何时：收到评审意见 / 这条评论对不对

作用：落实前先核验，含糊或可疑的不要照单全收。

wukong-review自动

何时：审这个 PR / 审一下分支

作用：先写意图摘要，按风险列发现，给出能不能合并。默认只出报告。

commit-pr自动

何时：提交 / 帮我 commit

作用：看 diff，写 conventional commit，需要时推送并开 PR。集成方式没定时先收尾分支，再给选项。

release手点 / 授权派发

何时：/release / 发版 / 创建 Release

作用：确认版本，写只含新增、改动、修复的发版说明，打 tag 并创建 GitHub Release。

④ 🎨 专项技能15 个

按任务描述匹配；白底虚线保持显式调用。

理解与架构

how手点 / 授权派发

何时：这是怎么工作的 / 教我这块代码

作用：点名后讲清子系统架构、入口和运行流程；普通讲解保持显式调用政策。

why手点 / 授权派发

何时：为什么是这样 / 我们为什么选了这个

作用：查设计理由和取舍，带引用。运行时怎么走用 how。

refactor-architecture手点 / 授权派发

何时：/refactor-architecture / 重构架构

作用：扫浅模块，出 HTML 报告，再逐个追问定案。

archify手点 / 授权派发

何时：画架构图 / 架构图

作用：把系统、流程和数据关系画成可交互 HTML 图，或制作单页讲解。

界面与真实操作

impeccable自动

何时：做页面 / 改界面

作用：也用于打磨、加动画、审查样式、落地页、设置页、空状态、无障碍和 INP。纯后端不用。

mcp-builder手点 / 授权派发

何时：写个 MCP Server

作用：设计工具契约，实现服务端并验证真实调用。
remotion-create手点 / 授权派发

何时：用 Remotion 做视频

作用：编排镜头、字幕和音轨，渲染并抽查成片。
control-ui自动

何时：打开浏览器点一遍 / 截个图

作用：用本地浏览器或 CDP 驱动网页、IDE 或 Electron。

control-cli自动

何时：驱动这个命令行 / 看看这个 TUI

作用：搭本地驾驭装置，不依赖外部服务，也可录一段终端演示。

专项审查与测试

e2e-testing自动

何时：写端到端测试 / Playwright 偶发失败

作用：给 React 或 Vue 写稳定的浏览器测试，后端可以是 Node、Go 或 Java。

Office 文档

docx手点 / 授权派发

何时：写个 Word / 做一份 docx

作用：创建、修改、审阅 Word；处理修订、批注、表格、图片和中文字体。

写作与表达

technical-writing手点 / 授权派发

何时：写 README / 写文档

作用：Markdown 和技术说明的分层标准。Word 用 docx。

wukong-proposal自动

何时：写个方案 / 技术方案

作用：先问清目标和读者，列提纲，再写成中文方案。Word 用 docx。

技能与会话维护

author-skill手点 / 授权派发

何时：/author-skill / 新建一个 skill

作用：按目录、name、description 和步骤写技能说明。文字写完按 technical-writing 的去 AI 腔清单过一遍。

reflect手点 / 授权派发

何时：/reflect / 把这次教训写进技能

作用：点名后深度复盘，提出已有技能的具体改法；经批准后应用。
