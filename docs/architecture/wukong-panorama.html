wukong 技能全景：一句话怎么走到技能，36 个技能各干什么

支持 Codex / Claude Code / Antigravity · 版本 1.0.38 · 20 个自动选用 / 16 个点名调用 · 先按任务匹配，必要时展开流程。

① 开始

用户任务、目标和已有授权。

↓
② 当前宿主与全局规则

先看可用技能与项目约定；不混读其他项目。

↓
③ 直接匹配或 wukong-router

有明确对口技能就直接加载；拿不准才走路由。

④ 判断（从上往下）

1. 点名了哪个技能？
→ 直接加载点名技能

2. 是明确的小改动吗？
→ 跳过方案与计划

3. 新功能或改行为？
→ 方案、计划、执行、自审

4. 跨模块、大迁移或要并行？
→ 用 executing-plans

点名技能

明确要用哪个：直接加载，不绕完整开发流程。

→
读取点名技能

显式技能只在点名或已授权工作流中使用。

→
按技能步骤处理

理解、文档、审查等各有对应能力。

→
适用验证

按任务类型与风险选档，不重复跑同一检查。

→
交付结果

说明产物、证据和实际限制。

小改动 · 快路

意图明确，1–2 个文件，不改接口、结构或依赖。

→
跳过方案与计划

只加载真正对口的技能。

→
直接处理

修 bug 仍先定位根因；界面沿用既有规范。

→
相称验证

文案等第 0 档只看 diff；代码按验证分档。

→
代码自审

第 0、1 档只看 diff；提交前过一遍 deslop。

中等任务 · 主流程

新功能、改行为或已有明确需求的多步任务。

→
brainstorming

澄清意图、目标与约束，确认设计。

→
writing-plans

拆成有文件、步骤与验收的实现计划。

→
按已确认方式执行

主任务执行；已有委派授权时才派实现者。

→
验证与自审

第 2 档验证所在模块，自审再看关键调用方。

→
授权后 Git 操作

commit-pr；没有授权不提交推送。

复杂任务 · executing-plans

跨模块、大迁移、要并行：按书面计划执行。

→
选择执行方式

主会话、子代理逐任务或可审计流程，按授权选择。

→
架构与隔离

实质未决时点名 architect；需要时先开 worktree。

→
并行协作

点名 swarm 时 Antigravity 原生群体协调；其他宿主用子代理派发。

→
全量验证

第 3 档全量测试一次，检查目标实际行为。

→
独立评审与收尾

自审后派只读子代理独立评审；Git 与清理看授权。

钩子：Claude Code 与 Antigravity 自动启用，Codex 手动配置
会话开始 → 只读检查全局规则是否缺失或过期 · 每条提示词 → 附评估说明，缺口明显才加载 prompt-sharpen · 执行 Bash 前 → 长命令提醒放后台，强制推送、--no-verify、reset --hard、git clean 与敏感文件/密钥/大文件提交先确认
本地使用日志存在 ~/.wukong/journal.db，不上传、不进对话；WUKONG_JOURNAL=0 关闭。

二、每个技能干什么

浅色实底＝可自动选用 白底虚线＝点名或已授权派发每张卡只列触发例子与职责摘要；点击卡片查看 SKILL.md，实际调用以其政策和当前授权为准。

① 🧭 入口与配置2 个

先匹配；初始化同步全局规则与子代理模型。

wukong-router自动

何时：拿不准 / 该用哪个 / 没有全局规则

作用：先直接匹配对口技能；拿不准或跨模块才路由，并按改动选验证档位。
wukong-init点名 / 授权派发

何时：/wukong-init / 新机器配置 / 配置子代理模型

作用：同步当前宿主的全局技能规则，按可用模型给检索、规划、审查、测试四个角色配模型和推理档位；整表确认后写入，保留其他配置。

② 🤝 工作模式3 个

只在点名或已授权工作流派发时使用。

架构与策略

architect点名 / 授权派发

何时：/architect / 先定模块边界

作用：写代码前勾勒类型、函数签名和模块结构，实现过程中一直参与。

长任务与交接

show-me-your-work点名 / 授权派发

何时：/show-me-your-work / 通宵跑完我回来看

作用：长时间或无人值守的工作，每个决定记一行。
handoff点名 / 授权派发

何时：/handoff / 写个交接文档 / 切新会话继续

作用：把目标、分支与精确提交状态、已验证结论和踩坑压缩成紧凑交接文档与下一会话提示词。

③ 🛠️ 开发主流程15 个

按任务需要选用，不代表必须整列执行。

需求到执行

prompt-sharpen自动

何时：需求太模糊 / 优化提示词

作用：目标、范围、约束或验收有关键缺口时，先读项目记录和代码自行补齐，必要时才提问并改写请求；已经清楚就跳过。
project-memory自动

何时：建项目档案 / 同步项目记录 / 架构文档过期了

作用：init 先确认再建档，sync 按 diff 只改受影响的部分，check 只读报告；沿用已有记录位置。
brainstorming自动

何时：做个新功能 / 改一下行为 / 先把方案想清楚

作用：动手前摸清意图、需求和设计，取舍范围，必要时重新设计这一层；含 4 条原则。
writing-plans自动

何时：写个实现计划 / 拆成小步

作用：已有规格的多步任务或迁移，先拆成每步都能验证的计划；含 2 条原则。
executing-plans自动

何时：按这份计划做 / 先开个 worktree / 反复检查直到通过 / /swarm 并行跑一遍

作用：主会话或子代理逐任务执行，隔离工作区，避免并行子代理共用文件，循环检查直到通过；点名 swarm 时按 Antigravity 原生群体协调者并行派工；含 3 条原则。

调试、测试与质量

systematic-debugging自动

何时：修 bug / 报错了 / 这个数字靠谱吗

作用：先复现、查根因再改，可疑的测量数字也先核实；含 4 条原则。
tdd自动

何时：先写失败测试 / 补个回归测试

作用：有便宜的本地测试点就先写会失败的测试再修。路径贵或说不清就跳过。
test-strategy自动

何时：测什么 / 放在哪一层测

作用：给功能或项目定每层用什么工具、哪些不测，并写出命令。覆盖 TypeScript、React、Vue、Go、Java；含 1 条原则。
code-style自动

何时：文件放哪 / 类型怎么设计 / 写成 lint 检查

作用：按模块就近放文件，含边界校验、类型与领域建模、幂等脚本、迁移不留兼容层和交付前自审；含 11 条设计原则。仓库规范优先。
deslop自动

何时：/deslop / 提交前清一下 AI 味

作用：清这次 diff 里的代码腔：多余注释、不该有的防御、过深嵌套。只清注释时派 comment-sicko 只读审查。

审查与收尾

requesting-code-review自动

何时：做完了帮我审查 / 合并前核验一下

作用：核对是否满足需求并拿出验证证据；第 3 档或高风险改动派只读子代理独立评审。
receiving-code-review自动

何时：收到评审意见 / 这条评论对不对

作用：落实前先核验，含糊或可疑的不要照单全收。
wukong-review自动

何时：审这个 PR / 审一下分支 / 安全审查

作用：先写意图摘要，按风险列发现（支持 --security 安全专项模式），给出能不能合并。默认只出报告。
commit-pr自动

何时：提交 / 开个 PR / 收尾这个分支

作用：看 diff，写 conventional commit，需要时推送并开 PR；集成方式没定时先核验，再给合并、PR、保留或丢弃的选项。
release点名 / 授权派发

何时：/release / 发版 / 打 tag

作用：按插件清单里的版本打 tag，写只含新增、改动、修复的发版说明，创建 GitHub Release。

④ 🎨 专项技能16 个

按任务描述匹配；白底虚线保持显式调用。

理解与架构

how点名 / 授权派发

何时：这是怎么工作的 / 走读一下

作用：讲子系统的架构、入口和运行流程，改之前先走读。问动机用 why。
why点名 / 授权派发

何时：为什么是这样 / 这个阈值哪来的

作用：查设计理由和取舍，带引用。运行时怎么走用 how。
refactor-architecture点名 / 授权派发

何时：/refactor-architecture / 模块耦合太紧

作用：扫浅模块和耦合，出 HTML 报告，再逐个追问定案。
archify点名 / 授权派发

何时：画架构图 / 时序图 / ER 图

作用：把系统、流程、调用链、表结构画成校验过的 HTML 图，或做结论先行的单页讲解。需要 Node 18+。
db-migration点名 / 授权派发

何时：/db-migration / 写数据库迁移 / 零停机迁移

作用：排查大表锁表、非空列与索引风险，按 expand-contract 零停机拆步并核对回滚。

界面与真实操作

impeccable自动

何时：做页面 / 改界面 / 卡顿掉帧

作用：设计、打磨、加动画、审查样式和无障碍；optimize 守 INP、长任务、帧率和包体积。纯后端不用。
control-ui自动

何时：打开浏览器点一遍 / 截个图

作用：用本地浏览器或 CDP 驱动网页、IDE 或 Electron 取证。
control-cli自动

何时：驱动这个命令行 / 看看这个 TUI

作用：搭本地驾驭装置，不依赖外部服务，也可录一段终端演示。
mcp-builder点名 / 授权派发

何时：写个 MCP Server

作用：设计工具契约，实现服务端并用 MCP 客户端联调。
remotion-create点名 / 授权派发

何时：用 Remotion 做视频

作用：用 React 编排镜头、字幕和音轨，渲染并抽查成片。

专项测试

e2e-testing自动

何时：写端到端测试 / Playwright 偶发失败

作用：给 React 或 Vue 写稳定的浏览器测试，修偶发失败和超时；后端可以是 Node、Go 或 Java。

文档与写作

docx点名 / 授权派发

何时：写个 Word / 改修订 / 加批注

作用：创建、修改、审阅 Word，含脚注、表格、图片和页面设置。中文设置 w:eastAsia。
technical-writing点名 / 授权派发

何时：写 README / 写 RFC / 去掉 AI 腔

作用：README、文档、RFC、PR 说明的分层写作标准，附去 AI 腔清单。Word 用 docx。
wukong-proposal自动

何时：写个方案 / 技术方案

作用：先问清目标和读者，列提纲，再写成中文方案。Word 用 docx。

技能维护

author-skill点名 / 授权派发

何时：/author-skill / 新建一个 skill

作用：按目录、name、description 和步骤写技能说明，写完过一遍去 AI 腔清单。
reflect点名 / 授权派发

何时：/reflect / 把这次教训写进技能 / --add 记个人规则

作用：单条小改走轻量快路，多处教训派三审查者深度复盘；--add 直接记个人规则，--me 从使用日志归纳。

共 36 个技能 · 2 个入口与配置 + 3 个工作模式 + 15 个开发主流程 + 16 个专项技能。
这是技能索引与调用路径示意，不是每轮必跑的流水线。文案等第 0 档只看 diff；代码改动先自审，第 3 档或高风险改动再加只读独立评审。初始化、提交推送与清理分别遵循各自授权。
