→

→

浅色实底＝可自动选用 白底虚线＝用户点名或已授权派发每张卡只列触发例子与职责摘要；点击卡片查看原始 SKILL.md，实际调用以其政策和当前授权为准。

① 入口与配置4 个

先匹配，再配置；经验按需回读。

s-router自动

何时：开始任何对话 / 先查技能

作用：先直接匹配对口技能；拿不准才路由，并选择相称的验证强度。

setup-s-instructions手点 / 授权派发

何时：/setup-s-instructions

作用：显式初始化或更新当前宿主的全局技能规则，保留用户其他配置。

setup-s-models自动

何时：/setup-s-models / 配置 s 模型

作用：检测真实可用模型，为各角色选择模型和推理预算，写入当前宿主配置。

learn自动

何时：记住这次教训 / 你又犯同样的错

作用：按需回读已确认经验；发现教训时只提建议，逐条确认后才保存。

② 工作模式8 个

仅点名或已授权工作流派发时使用。

加强工作流

s-mode手点 / 授权派发

何时：/s-mode / 用 s-mode

作用：点名才走的加强工作流：子智能体、去掉 AI 腔、简单代码、做完要验证。

s-agent手点 / 授权派发

何时：派一个 s-agent / 让子智能体去写

作用：s-mode 派出去写代码或打杂。动手前读完 s-mode，不要派它跑 playbook。

架构与策略

architect手点 / 授权派发

何时：/architect / 给这个做架构

作用：写代码前勾勒类型、函数签名和模块结构，实现过程中一直参与。

figure-it-out手点 / 授权派发

何时：/figure-it-out / 没有现成流程

作用：大规模迁移或人离开后要审的活，现做一套可审计做法。

swarm手点 / 授权派发

何时：/swarm / 并行跑一遍

作用：同时派 N 个工作者，等齐了交一份报告。

arena手点 / 授权派发

何时：/arena / 扔进竞技场

作用：同一任务并行出候选，选一个做底，把其余长处接进去。

长任务与记录

timed-loop手点 / 授权派发

何时：/timed-loop / /loop

作用：按通过或失败条件反复醒来。一段时长不算完成。

show-me-your-work手点 / 授权派发

何时：/show-me-your-work / 留下决定记录

作用：长时间或无人值守的工作，每个决定记一行。

③ 开发主流程15 个

按任务需要选用，不代表必须整列执行。

需求到执行

brainstorming自动

何时：做个新功能 / 加个接口

作用：先摸清需求、目标和约束，确认设计；明确的小改动按快路处理。

writing-plans自动

何时：写个实现计划 / 先拆步骤

作用：已有规格、要做多步任务时，先写成可执行计划。

using-git-worktrees自动

何时：开个 worktree / 和当前工作区分开

作用：需要隔离时准备工作区；优先复用已有合适位置，保留用户修改。

executing-plans自动

何时：按计划在新会话做 / 执行这份实现计划

作用：主任务在当前或接续会话按书面计划和检查点执行。已授权派子智能体时用 subagent-driven-development。

subagent-driven-development自动

何时：在这个会话里派子智能体做

作用：在已有实现委派授权时分派独立任务，跟踪进度并完成任务评审。

调试、测试与质量

systematic-debugging自动

何时：修 bug / 报错了

作用：先查根因再改。bug-fix 和 fix bug 也走这里。

tdd自动

何时：先写失败测试 / 补个回归测试

作用：有便宜的本地测试点就先写会失败的测试再修。路径贵或说不清就跳过。

test-strategy自动

何时：测什么 / 放在哪一层测

作用：给功能或项目定每层用什么工具、哪些不测，并写出命令。覆盖 TypeScript、React、Vue、Go、Java。

code-style自动

何时：文件放哪 / 补文档注释

作用：按模块就近放文件，遵循已有规范；交付前自审完整差异和关键调用方。

deslop自动

何时：/deslop / 提交前清一下 AI 味

作用：清这次 diff 里的代码腔：多余注释、不该有的防御、过深嵌套。文字腔用 /unslop，只清注释用 /no-comments。

审查与收尾

requesting-code-review自动

何时：做完了帮我审查 / 合并前核验一下

作用：代码交付前派只读评审者核对完整差异与关键调用方，风险决定范围。

receiving-code-review自动

何时：收到评审意见 / 这条评论对不对

作用：落实前先核验，含糊或可疑的不要照单全收。

s-review自动

何时：审这个 PR / 审一下分支

作用：先写意图摘要，按风险列发现，给出能不能合并。默认只出报告。

commit-pr自动

何时：提交 / 帮我 commit

作用：看 diff，写 conventional commit，需要时推送并开 PR。分支怎么集成还没定，用 finishing-a-development-branch。

finishing-a-development-branch自动

何时：做完了怎么合 / 开 PR 还是合并

作用：完成适用验证、还没定集成方式时，给出合并、PR 或清理的选项。

④ 专项技能28 个

按任务描述匹配；白底虚线保持显式调用。

理解与架构

how手点 / 授权派发

何时：这是怎么工作的 / 教我这块代码

作用：点名后讲清子系统架构、入口和运行流程；普通讲解保持显式调用政策。

why手点 / 授权派发

何时：为什么是这样 / 我们为什么选了这个

作用：查设计理由和取舍，带引用。运行时怎么走用 how。

refactor-architecture手点 / 授权派发

何时：/refactor-architecture / 重构架构

作用：扫浅模块，出 HTML 报告，再逐个追问定案。

archify自动

何时：画架构图 / 架构图

作用：把系统、流程和数据关系画成可交互 HTML 图，或制作单页讲解。

界面与真实操作

impeccable自动

何时：做页面 / 改界面

作用：也用于打磨、加动画、审查样式、落地页、设置页、空状态、无障碍和 INP。纯后端不用。

apple-glass自动

何时：影盒风格 / 按 yingbox 的 UI 做

作用：按影盒（yingbox）的设计语言做界面：深色优先、纯黑底、实色卡片、玻璃只给浮动控件、8pt 间距、令牌化、组件化。

frontend-design手点 / 授权派发

何时：点名 frontend-design / 给个视觉方向

作用：只在点名时定配色、字体和版式，不带检查脚本。日常做界面用 impeccable。

html-mockup自动

何时：先出图 / 做个设计图

作用：手写 HTML/CSS 出静态设计稿或固定尺寸素材，以浏览器截图交付。

control-ui自动

何时：打开浏览器点一遍 / 截个图

作用：用本地浏览器或 CDP 驱动网页、IDE 或 Electron。

control-cli自动

何时：驱动这个命令行 / 看看这个 TUI

作用：搭本地驾驭装置，不依赖外部服务，也可录一段终端演示。

专项审查与测试

e2e-testing自动

何时：写端到端测试 / Playwright 偶发失败

作用：给 React 或 Vue 写稳定的浏览器测试，后端可以是 Node、Go 或 Java。

benchmark-checklist手点 / 授权派发

何时：跑了基准测试 / 这个加速靠谱吗

作用：先审核限制因素、调优、误差、可重复性，以及量的是不是那项工作。

no-comments手点 / 授权派发

何时：/no-comments / 审查前先删注释

作用：派 comment-sicko 只读审查，由父任务核实并处理注释。连防御和 any 一起清，用 /deslop。

comment-sicko手点 / 授权派发

何时：派 comment-sicko / 删掉不该留的注释

作用：被 /no-comments 派去只读审查 diff，报告候选删除和重塑目标。不要当主对话跑。

interrogate手点 / 授权派发

何时：/interrogate / 对抗式审查

作用：多个模型从各自角度挑战改动。

Office 与专利

docx自动

何时：写个 Word / 做一份 docx

作用：创建、修改、审阅 Word；处理修订、批注、表格、图片和中文字体。

pptx自动

何时：做幻灯片 / 做一份 PPT

作用：创建、修改、阅读 PowerPoint，处理模板、布局与演讲备注。

xlsx自动

何时：做表格 / 做个 Excel

作用：创建和分析表格；派生数字使用公式，保存后重算并验证结果。

pdf自动

何时：读这份 PDF / 填 PDF 表

作用：提取文字和表格、填写表单，以及压平、旋转、盖章和加密。

patent-disclosure自动

何时：写专利交底书 / 专利挖掘

作用：挖掘中国发明专利保护点、查新并撰写技术交底书。

patent-application自动

何时：写专利申请 / 权利要求书

作用：起草中国发明专利申请文件，匹配模板并处理专利附图和版式。

写作与表达

technical-writing自动

何时：写 README / 写文档

作用：Markdown 和技术说明的分层标准。Word 用 docx。

s-proposal自动

何时：写个方案 / 技术方案

作用：先问清目标和读者，列提纲，再写成中文方案。Word 用 docx，幻灯片用 pptx。

translate自动

何时：翻译成英文 / 译成中文

作用：代码、命令、路径和 Markdown 结构保持原样，中文用白话。

unslop手点 / 授权派发

何时：/unslop / 去掉 AI 腔

作用：改写文字，让它像人写的。

技能与会话维护

author-skill手点 / 授权派发

何时：/author-skill / 新建一个 skill

作用：按目录、name、description 和步骤写技能说明。文字写完用 /unslop。

reflect手点 / 授权派发

ketchup手点 / 授权派发

⑤ 原则 principle-*24 个

按具体问题选用；卡片标题省略共同前缀。

attack-the-premise自动

何时：同一前提修了两次都不对 / 先验证这个前提

作用：写下这个前提并直接验证，再写下一个默认它成立的修复。

boundary-discipline自动

何时：校验放在边界上 / 别在内部到处防御

作用：入口解析外部输入；由负责的操作保证业务不变量、权限和可变状态。

build-the-lever自动

何时：别手工改 / 做成脚本

作用：不简单的活做成可再跑的工具，审查者能重跑。

encode-lessons-in-structure自动

何时：这是第二次犯 / 写成检查

作用：把反复出现的规则写成 lint、标记或脚本。

exhaust-the-design-space自动

何时：没有先例 / 先做几个方案比比

作用：职责、状态或接口实质未决时，先比较少量方案，不强制多稿。

experience-first自动

何时：为用户着想 / 别为了好写而将就

作用：产品和范围上的取舍，选让人用着顺的，少做但做好。

explain-the-number自动

何时：这个数字靠谱吗 / 加速比哪来的

作用：报告或依赖测量数字前，核对限制因素、条件和数字实际含义。

fix-root-causes自动

何时：别打补丁 / 找到第一次出错的地方

作用：调试时把症状追到系统第一次出错的地方。

foundational-thinking自动

何时：先定数据结构 / 写逻辑之前

作用：先选核心类型和参与者共享了什么，再写逻辑。

guard-the-context-window自动

何时：上下文要满了 / 输出太长

作用：大段输出、长文件和计划只在主线程留摘要。

laziness-protocol自动

何时：能删就删 / 最小改动

作用：重构或评估改动时，留能解决问题的最小改动。

make-operations-idempotent自动

何时：崩溃重试 / 做成幂等

作用：命令、生命周期或循环中断后续跑，要落到同一结果。

migrate-callers-then-delete-legacy-apis自动

何时：迁完调用方再删旧接口 / 别留兼容层

作用：引入新的内部 API 时，同一轮迁完调用方并删掉旧的。

minimize-reader-load自动

何时：这代码绕 / 层数太多

作用：审查难追的代码时，去掉没有独立职责的转手包装，缩小可变状态。

model-the-domain自动

何时：状态散落各处 / 同一个假设写了好几遍

作用：把重复的数据形状收成一个结构。

never-block-on-the-human自动

何时：先做出来我再看 / 可撤销的别问我

作用：在已有授权范围内先完成可撤销工作；必要的确认仍然保留。

outcome-oriented-execution自动

何时：直接改到目标结构 / 别搞过渡兼容

作用：有阶段边界的重写和迁移，直接走向目标架构。

prove-it-works自动

何时：跑一遍证明它好了 / 别只说编译过了

作用：宣布完成前，对照真实产物核验。

redesign-from-first-principles自动

何时：新需求按第一性原理重做 / 别补在旧形状上

作用：把新需求整合进已有设计时，重做这一层。

separate-before-serializing-shared-state自动

何时：别一起写同一个文件 / 先去掉共享

作用：多个并发参与者可能写同一文件、分支、键或对象时，先消除共享。

sequence-verifiable-units自动

何时：拆成小步 / 一步一验

作用：批量清理、迁移或一串相似改动，每步停在可验证的状态。

subtract-before-you-add自动

何时：先删再加 / 死代码先清掉

作用：新增、重构或重写之前，先删掉死代码、多余校验和空壳引用。

test-behavior-not-implementation自动

何时：测行为别测实现 / 内部改了测试不该挂

作用：断言使用者能看到的东西。

type-system-discipline自动

何时：让非法状态写不出来 / 类型怎么设计

作用：设计类型或签名时，在边界上解析外部数据，穷尽变体。
