# 竞技场

在启动任何东西之前，先开一个待办清单，每个阶段一条（定框架、分派、交叉评审、选基础、嫁接、验证）。

## 阶段 A：定框架

每个候选者拿到的提示词都一样，所以提示词就是约定。

1. 说明每个候选者要产出的是什么产物。
2. 推导出评分标准：3-6 条具体的、可以打分的标准，说明在*这个*任务上成功是什么样子。它是阶段 D 里挑选者用的工具。候选者只看到任务本身。
3. 选择参赛者。用 `~/.cursor/rules/pstack-models.mdc` 里的 `arena runners` 那一行。如果这条规则或那一行不存在，默认 `claude-opus-5-5-xhigh` 和 `grok-4.7-xhigh-fast` 各一个。这一行或交叉评审那一行里如果写的是 `auto` 或 `inherit-parent`，就表示用父级的模型，所以对它省略 `model`。如果 Task 工具拒绝了某个配置的条目，就让那个席位用它所在系列的默认模型，并说明一下。系列按前缀划分：`claude-*` 是一个系列；`grok-*` 和 `cursor-grok-*`、`composer-*` 是一个系列。被拒绝的 `composer-*` 条目改用 `grok-4.7-xhigh-fast`。如果找不到匹配的系列，就用 `claude-opus-5-5-xhigh`。如果它连默认的也拒绝，就从它的报错信息里选同一系列中最接近的有效模型名。当竞技场要覆盖多个设计方向时，多派一些参赛者。如果这份工作主要受生成量限制、而不是对判断力敏感，就把同一个模型用 N 次。按 **poteto工作模式** skill 里 “Subagents” 一节的规定，为每个子智能体的任务选择推理等级，以及快速还是标准速度。
4. 按照 **separate-before-serializing-shared-state** 原则 skill，给每个候选者一个它自己的输出位置（尽量用一个 git worktree，否则用 `/tmp/arena-<slug>/candidate-<n>/`）。

## 阶段 B：分派

在一条消息里用 `run_in_background: true` 派出全部 N 个子智能体。每个都给：任务、共享背景资料的路径、它自己的输出路径，以及这样的指示：产出这个产物，并写一段简短的理由，说明它考虑过哪些备选方案、否定了哪些。

如果某个候选者没有产出，就用剩下的 N-1 个继续，并注明这个掉线。

## 阶段 C：交叉评审

阶段 B 的所有候选者都完成后，从 `~/.cursor/rules/pstack-models.mdc` 里的 `arena cross-judge pool` 那一行选一个模型。如果这条规则或那一行不存在，就从 `claude-opus-5-5-xhigh` 和 `grok-4.7-xhigh-fast` 里选。优先选和父级不同系列的模型。在那个模型上派出一个只读的评审子智能体。它看到评分标准和按路径标签区分的各个候选者，逐条打分，并推荐一个基础，附上理由。它和你在阶段 D 的阅读并行进行。候选者还在写的时候，不要派出它。

## 阶段 D：选基础

在挑选之前，把每个候选者从头到尾读完。对照评分标准一条一条给每个候选者打分，而不是凭整体感觉，然后和交叉评审的结果比较。在基础的选择上意见一致，就确认了这个选择。意见不一致，说明你们当中有一方有偏差，或者评分标准有歧义。做决定之前，把双方的理由都读一遍。

选那个未来的维护者最容易在不破坏不变量的前提下扩展的基础。如果两个感觉不相上下，按照偷懒守则（Laziness Protocol），选边界更干净或 API 更小的那个。

## 阶段 E：嫁接

把每个落选的候选者再过一遍，找出值得移植到基础里的东西，通常每个候选者一两样，而不是大部分内容。按照 **redesign-from-first-principles** 原则 skill，亲手把每一处嫁接融进去，让结果在同一个心智模型下保持连贯。不要机械地粘贴。

如果候选者都收敛到同一个形状，那就是很强的一致意见。记下这一点，直接交付这个共识形状。不需要嫁接。如果它们差得天南地北，说明阶段 A 的要求写得不够清楚。重新定框架再跑一遍，而不是把分歧取个平均。

## 阶段 F：验证

按照 **prove-it-works** 原则 skill，像验证任何其他产出一样验证这个综合出来的产物。如果验证发现了竞技场漏掉的问题，要么是阶段 A 错了（重新定框架再跑），要么是某个候选者其实抓到了它、而你漏了这次嫁接（回到阶段 E）。不要糊弄过去。

## 产出

一个综合出来的产物，旁边附一段简短的综合说明，写明：选了哪个作为基础以及原因、交叉评审的结论、每一处嫁接以及它来自哪个候选者、否定了什么以及原因、任何收敛或掉线的情况，以及验证结果。
