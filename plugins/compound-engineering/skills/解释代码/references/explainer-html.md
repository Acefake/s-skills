# 说明文档的 HTML 渲染

> 翻译自 Compound Engineering 插件（编号 680）的 `解释代码` skill 参考文件，原作者 Kieran Klaassen 和 Trevin Chow（版权 © 2025 Every），许可证 MIT，仅供自用。

说明文档怎样渲染成 HTML。在写的时候加载，不要更早。这些要求让一份独立的产物方便带走，并且如实说明它的来源。

## 硬性规定

- **单个、自包含的 HTML5 文件。** 不要配套的 `.css`、`.js` 或 `.svg` 文件。CSS 放在 `<style>` 里。SVG 直接内嵌。图片用 base64 data URI 或内嵌 SVG。不发出任何外部请求——说明文档在离线时、在有 CSP（内容安全策略）限制的查看器里，看起来都必须一模一样，所以和计划产物的约定不同，这里**没有网络字体的例外**：用系统字体。
- **所有元数据都以可见文字出现——唯一的数据来源。** 可见的 `<h1>` 就是标题。一个可见的页头 `<dl>` 使用确切的字段标签 `Date`、`Input shape` 和 `Subject`；`Input shape` 只能是 `concept`、`diff`、`idea` 或 `recap` 之一，`Subject` 写明话题、引用或回顾的时间段。当证据退回到了模型知识时，同一个页头还要带上标签 `Unverified — from model knowledge, not checked against current sources`。当请求指定了另一个读者时，页头再加一行，标签正好是 `Rendered for`，写明那个读者；给用户本人看的版本，整行都不要，而不是写“用户”。不要隐藏的机器可读副本：没有 JSON 脚本块，没有 `data-*` 镜像，没有重复的 `<meta>`。保持这些现有的产物字段名和枚举值不变。不要自己发明额外的元数据行。
- **只用来展示。** 没有表单、点击处理、交互式测验、“提交”按钮或脚本。“检查理解”如果有，就是 `references/check-in.md` 负责的那一节静态 `Check yourself`：先问题，后答案，全是可见文字。
- **ASCII 标识符。** class 名和元素 ID 只用 ASCII 字符。
- **写作标记。** 一个可见的页脚写明写作时间和写它的 skill：`Composed 2026-07-02 by ce-explain`。

## 呈现

深度、语气和版式由 skill 正文里关于读者的约定决定。给读者足够的项目背景，让他不看原来的对话也能看懂解释。按读者已经知道的东西来调整这些背景。

当图示能让解释更清楚时就用。遵守这些 HTML 渲染要求：

- 文字每行保持在 70 个字符左右，文字块用 `max-width: 70ch`。图示和代码可以用满宽度。
- 图示用内嵌 SVG。标签要清楚易读、对比度足够，需要时在文字后面加一圈光晕（halo）。
- 代码示例要做语法高亮，用文件 `<style>` 块里定义的 class，不用脚本或外部资源。

图示是文字的补充；跳过图示的读者，也能从文字里得到完整的解释。保留来源引用。讲项目行为时用检查过的证据里的真实代码。自己编的最小示例只用于外部话题，并标明它们是示例。

当证据超出要求的范围或深度时，挑出相关的线索，并说明省略了什么。绝不要悄悄去掉回顾的后半段，然后把它当成整个时间段来呈现。

## 写完后的检查

核实文件能单独打开，不请求任何外部资源，并带有要求的可见元数据。检查每个图示都有对应的文字说明。普通的来源超链接是允许的；离线可读性不能依赖去打开它们。
