# 证据和分派

在收集证据或分派任务之前读。skill 正文负责互动、完成标准和临时目录的创建；这份参考文件负责证据收集，以及各种功能缺失时的退回方案。

## 互动方式

是否需要提问，由 skill 正文的互动规则决定。需要提问时，使用运行环境当前工具列表里已有的提问功能；绝不要为了确认它存不存在而去调用面向用户的提问工具。如果没有这种工具，只有在有人参与时才在聊天里提问。否则，就把缺少的信息返回给调用它的流程。

## 模型分档

按任务的类型分档派发，绝不写死某个模型名字：

- **提取档（Extraction tier）**——工作回顾侦察员和每个行为追踪侦察员：做的是搜索和引用的工作。如果运行环境提供已知的覆盖设置，就用平台上最便宜但够用的模型；否则沿用上层模型。
- **最高档（Ceiling tier）**——写说明文档，包括其中的 `Check yourself`（自我检查）一节。这部分在主对话里用编排者自己的模型运行；不为它派发任何东西。

**降级规则。** 当平台的子智能体功能不能给每个智能体单独选模型时，就用沿用来的模型派出侦察员，并保持它们的阅读预算。当平台根本没有子智能体功能时，就在当前上下文里直接做侦察工作，预算不变。派发失败时，把并发数或活动智能体数量上限的报错当作“排队等待”——等有空位再试；如果启动失败的原因在改正调用方式后仍然存在，就在当前上下文里直接做那个侦察员的工作，预算不变，并用一句话说明。

## 按输入类型收集证据

**和仓库有关的输入**（在这个仓库里有关联的概念、一个改动、一次回顾）：使用上下文里项目当前有效的说明，直接去看改动、调用位置、当前源代码或提交记录。当规范用词很重要时，读 `CONCEPTS.md`。如果凭输入和现有上下文无法确定话题范围，允许做一次有针对性的根目录或工作区探查。

**Diff 模式：** 确定这个改动（`diff:` 的引用；或者当请求隐含地指向某个改动时，用最近一次较大的改动），并收集它的证据——改动本身、它涉及的文件、促成它的任何计划或解决方案文档。

**Recap 模式：** 以 `references/agents/work-recap-scout.md` 作为侦察员的起点（提取档），传给它确定好的时间段、仓库根目录和 `$RUN_DIR`。它会返回一份带有提交 sha 和 `file:line` 指引的证据摘要，并写出 `recap-evidence.md`。**时间段内没有活动**时按 skill 正文处理：报告没有活动，不产出说明文档。

**外部概念**（和这个仓库无关）：完全跳过在仓库里找证据——不要把仓库背景硬塞进输出里。用能用的网络工具做调研。如果一个都没有，可以凭模型自己的知识解释，但要在回答或产物的元数据里标注 **Unverified — from model knowledge, not checked against current sources**（未核实——来自模型知识，没有对照当前资料检查）。

**Idea 模式：** 想法是固定的前提。为了帮用户理解，解释它的影响、运作方式和取舍。绝不要去划定它的范围（那是 `头脑风暴` 的事），也绝不要想出替代方案并排名（那是 `ce-ideate` 的事）。

## 行为和理由

对于“怎么样”的问题，从相关的触发点开始，追踪它经过的状态变化、负责范围的边界，直到产生的效果。要看实际的源代码和相关测试；文件名或对话里的说法不能证明行为。保留对预定用途有影响的条件和失败路径。

如果一轮追踪就能说清那些边界、不需要含糊带过，一轮就够了。如果一轮做不到，就按答案所依赖的每个负责范围边界，把问题切成一片一片，每片派一个行为追踪侦察员。读 `references/agents/behavior-trace-scout.md`，用提取档的模型派出一个通用子智能体，传给它问题、它负责的那一片，以及 `$RUN_DIR` 下一个单独的证据档案路径。所有分片一起派出。最少切成两片。超过四片说明问题的范围还没划清：先缩小问题再追踪，而不是加侦察员。从各自的路径读每份证据档案，有重叠或矛盾的地方，去读源代码来调和。一个大概的意思不等于追踪。

对于“为什么”的问题，去找做决定时的记录：促成它的文档、代码注释、git 历史、PR 讨论或关联的 issue。当本地记录回答不了问题时，在请求允许的来源范围内，顺着证据去找能找到的来源。能访问团队聊天，不等于可以去搜索它——如果调用的流程把它设为需要主动开启的话。扩大调查是为了补上重要的缺口，不是为了凑够来源数量。

代码展示的是行为，不一定是意图。把有文档记载的理由，和有依据的推断分开引用；报告矛盾和不知道的地方。搜不到结果不能证明没有理由。在把一个历史上的限制当成当前要求之前，先确认它现在是否还适用。当这份解释会影响一次改动时，把相关的限制条件和没解决的风险整理成下一步能直接用的样子，但不替下一步选择做法。
