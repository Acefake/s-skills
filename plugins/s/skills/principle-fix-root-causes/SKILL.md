# 修根本原因

调试时，修的是故障本身，而不是它露出来的地方。症状是错误状态变得可见的地方。根本原因是系统第一次做了不该做的事、或者没处理好本该处理的状态的地方。

**为什么：** 只修症状会掩盖证据，故障还可以在别处冒出来。每做一次这样的修补，系统就更难推理，因为代码里多了一个绕过 bug 的办法，而这个 bug 谁也没有说出名字。

**做法：**
- 先复现。
- 每一步都问“为什么”，一直问到答案是代码里的一个错误决定，而不是更早某个错误的后果。
- 卡住时，加观测手段。读真实的报错和真实的状态。不要猜。
- 问一问触发症状的那个状态是否合理。如果系统可能处在那个状态，那么在它上面出错的代码就是根本原因，在那里处理这个状态就是修复。如果这个状态根本不该存在，在出错的地方加检查就是掩盖 bug。要找到是什么产生了这个状态。防护、重试、吞掉错误、把数值强行限制在范围内、丢弃状态，是掩盖 bug 的常见手法。
- 如果只在重启后才失败，先怀疑持久化的状态：配置文件、缓存、锁文件、序列化保存的状态。
- 检查的是模式，而不只是这一个实例。找出所有有同样故障的地方，全部修掉。
- 如果一个绕过办法需要一整段注释来解释为什么这样做，那就是代码错了。修代码，而不是修注释。
- 如果找到关键事实需要深挖很久，就提出一个便宜的、一直开着的信号，让人第一眼就能看到它。
