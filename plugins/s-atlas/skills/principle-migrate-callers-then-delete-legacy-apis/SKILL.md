# 先迁移调用方，再删掉旧API

引入新的内部API时，同一轮完成调用方迁移并移除旧接口，避免长期维护两个表达同一件事的入口。

## 适用条件

- 没有外部用户依赖向后兼容。
- 项目能承受一次协调好的不兼容改动。
- 新API属于这次简化或重构的范围。

条件不成立或调用范围未知时，先确认兼容要求，不擅自删除公开接口。

## 做法

1. **明确新约定。** 写出新旧接口的输入、输出、错误和行为差异，以及本轮需要同步的部分。
2. **清点调用方。** 查源码、导出、注册入口、动态调用、测试、示例和文档；记录不能靠文本搜索确认的使用方。
3. **迁移调用方与测试。** 改用新接口，让测试断言新约定；只保护旧实现细节的测试重写或删除，保留用户行为和兼容边界的检查。
4. **确认没有旧依赖。** 核对调用清单并再次搜索，检查运行时注册等间接路径。未知使用方不能记为“零调用”。
5. **删除旧API及相关残留。** 移除旧导出、无用适配、旧示例和过时说明，不留下没有调用方的兼容壳。
6. **验证。** 按仓库约定运行类型或静态检查、相关行为测试；检查层级遵循[s-router](../s-router/SKILL.md)，验证真实调用方仍满足新约定。

## 完成标准

报告已迁移的调用范围、旧入口删除情况和验证结果；有未确认的使用方时明确指出，不能宣称迁移完成。
