# 中英翻译

翻译已经写好的文字。不新写技术方案，不排 Word。技术说明的句子标准是 `technical-writing`。`.docx` 用 `docx`。

## 步骤

1. 确认方向：中文到英文、英文到中文，或中英对照。用户没说，就问这一句，不要猜。
2. 对照时，两种语言都是完整的正文。用户要逐段对照，就一段中文接一段英文，顺序跟原文一致。用户没指定格式，就先给目标语言的完整译文。
3. 译完自己读一遍。数字、否定、条件、单位和专有名词要还在。删掉翻译腔。

## 保持不动的部分

- 代码块、命令、路径、标识符、URL、配置键、frontmatter 的键。
- Markdown 的标题层级、列表、表格、链接目标和图片路径。
- 文件名和技能目录名。本仓库的技能名是英文小写 kebab-case，不要译成中文目录。

说明性的正文要译。代码块里的注释，只有用户明确要求时才译。

## 中文

用白话和短句。一个句子一个意思。不写「进行」「旨在」「该」「如下所示」。专有名词第一次出现可以在后面括注原文，之后只用一个名字。不省略原文里的条件。拿不准的术语保留英文，并括注你的理解。

## 英文

句子给没看过中文的读者也能独立读懂。不按中文的词序硬套。条件放在动作前面。不发明原文没有的语气。

## 边界

- 不改事实，不合并原文分开的警告。
- 不把翻译和改写混成一次。用户要的是改写，就先说明你改了哪一层意思。
- 产品界面上的文案不是这里的文档翻译。

## 在不同软件里怎么用

Cursor、OpenCode、Codex、Claude Code、WorkBuddy 都在对话里给出译文。不要依赖某个软件自带的翻译命令。
