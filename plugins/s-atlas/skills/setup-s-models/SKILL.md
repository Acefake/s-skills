## 运行环境适配

涉及宿主工具、模型配置或子代理时，按需阅读[宿主适配](../../HOSTS.md)。

# 设置 s 的模型

给 18 个角色选定模型和预算，写入当前宿主会读的标记段。路径、以及标记外的内容能不能动，以[宿主适配](../../HOSTS.md)为准。写出的起止标记是 `# s 模型配置` 到 `# s 模型配置结束`，旧英文标记仍可读取。重新配置只替换这一段，默认保留已有角色模型；用户明确选择重新分配才用新推荐覆盖，单行修改用 `--set`。中文键优先，只有一头标记时停止并保留原文。Codex 的 `s-*.toml` 文件名仍按英文键生成，见该参考。

只写这次确认可用于子代理的模型名。`inherit-parent` 和 `auto` 始终合法，派子代理时不传模型。一个都检测不到，保留已有设置或使用继承模式；不能把用户提供但工具不接受的名字写成已验证可用。旧 17 行配置继续有效，缺少轻量角色时不自动补写，派发沿用原工作流角色。18 行以外的旧角色不写回去。

## 三档模型推荐

先核对当前宿主实际可派发的模型、工具与推理档位，再推荐轻量、常规、复杂三档。依据可验证的能力定位与当前可用性，不按名字前缀推断强弱，不写死某一厂商或某一型号。成本资料不足时不声称某模型最便宜。只有一两个合适模型时允许共用，无法按次指定模型时使用 `--inherit`，并说明本次没有模型分流。

- 轻量档用于“检索和简单任务”：范围和操作规则明确、结果容易核对、不需要自行判断业务语义。能用搜索或脚本直接完成时不额外委派。
- 常规档用于日常实现和需要理解上下文的探索，参数仍为 `--fast`。
- 复杂档用于困难实现、跨模块分析和综合判断，参数仍为 `--strong`。复杂实现使用“最难的任务”，不把强模型限定为写作专用。

轻量参数为 `--light`，省略时用常规模型。`--third` 只用于不限预算的额外评审，不是轻量档。三档不决定子代理人数，也不授权委派。实际分类和优先级见[公共派发规则](../s-mode/references/subagents.md)。

先列出这次真能传给子代理的模型。Claude Code 没有列模型的工具：候选以这次 `Agent` 工具定义里 `model` 的取值为准（常见是 `sonnet`、`opus`、`haiku`），定义里没有的名字不写，也不收用户贴的完整模型 ID。把这份候选先告诉用户，再进入下一步。中英角色键见[角色键对照](references/role-keys.md)。写出用中文键，读取时中文键优先。

## 一次一问

用宿主的提问工具，一次一步。没有就给编号，等回复。每步都能跳过，但第 3、4 步必须各自单独问一次：不能因为前面选了预算、跳过了某步，或用户说「随便」，就把展示和确认合并或略过。

1. **确认宿主。** 说出检测到的软件。选项是它，加上 Codex、Claude Code、Cursor、WorkBuddy、DeepSeek Harness（`dsh`）、Hermes agent（`hermes`）。两个都像，或和前四个冲突，就停在这里问。跳过时：检测明确就用它，否则不写文件。Codex、Claude Code、Cursor、WorkBuddy 的路径和派法不变，见各自参考。

   **dsh。** 家目录是 `$DSH_HOME`，否则 `~/.dsh`。技能在 `$DSH_HOME/skills/<name>/SKILL.md`。标记段只写 `$DSH_HOME/AGENTS.md`，不写任何 `cordis.patch.yml`。`profiles/` 下多于一个已有目录就问用哪一个；只对那个目录运行 `dsh --profile <name> --dump-config` 和 `--dump-config-schema`。能按次换模型时，角色行写 `<provider>/<model>`。不能换时写 `inherit-parent`，不传 provider 和 model；工具有 `reasoning_effort` 就只传映射后的档位。名单用 `list_subagent_models` 或 dump 里的允许路线。字段和未确认项见 [dsh 参考](../s-router/references/dsh-tools.md)。

   **Hermes。** 家目录是 `$HERMES_HOME`，否则 `~/.hermes`。`hermes profile list` 多于一个就问。技能在该家的 `skills/`。标记段只写该家的 `SOUL.md`，不改 `config.yaml`。默认不能按次传模型，18 行都写 `inherit-parent`，不传模型和档位。名单用 `hermes -p <name> config get`，不要加 `--raw`。见 [Hermes 参考](../s-router/references/hermes-tools.md)。

2. **选预算。** 只问这一题，不问套餐或订阅。已有预算先说出来。额度有限的套餐建议选「省」，或在下一步把 18 行都改成 `inherit-parent`。默认是「大」。跳过则 `# 预算` 写 `inherit-parent`，不改模型名后缀；下一步先按「大」的角色分工和 2 项评审组来填，后缀用检测结果里原有的名字。

   选择卡片里，每一档都带上下面这一行说明，原文照抄：

   - 省：评审只派 1 个快模型，最难的活用强模型，最省额度
   - 中：评审派 1-2 个，判断类用强模型
   - 大：评审派 2 个（一快一强），默认
   - 不限：评审 2 个以上，思考最深，最费额度

   在展示角色配置前说明本次三档推荐及依据。常规模型沿用原快模型参数；复杂模型沿用原强模型参数。常规角色：`写功能和重构`、`修 bug`、`性能问题`、`爬坡优化`、`怎么工作的探索者`、`为什么的调查者`、`反思的工具视角`、`群体作战的工作者`。判断角色：`判断和写作`、`最难的任务`、`怎么工作的讲解者`、`为什么的综合者`、`反思的判断、发散和综合`。原有预算分配保持不变，新增轻量角色不加入评审列表。评审组这四行用同一份列表：`竞技场参赛者`、`架构设计参赛者`、`审问审查者`、`竞技场交叉评审`。逗号分隔的每一项派一个子代理；竞技场交叉评审从中选一项。

   Codex、Cursor、WorkBuddy 把推理目标写进模型名后缀：省 medium，中 high，大 xhigh，不限 max。以 `fast` 结尾时看前一段。没有刚好的后缀，就用同一系列里不超过目标的最高已检测名字。系列没有这种后缀时，保留检测到的名字，依据可验证的能力定位选择，不凭名字推断排序或成本。只有一个名字就不动，并说明没有档位。Claude Code、DeepSeek Harness 和 Hermes 不改名字后缀；括号里写映射后的档位，宿主没有该档就按参考下调。Claude Code 的模型只写别名或完整 ID，档位由派发时的 `effort` 参数携带，见 [Claude Code 参考](../s-router/references/claude-code-tools.md)。

   省的四条评审行都写上，恰好 1 项快模型，不留空、不删行。只有 `最难的任务` 用强模型；推理按 medium，`最难的任务` 自动高一档（写成 high）。中、大、不限时，`判断和写作`、`最难的任务`、`怎么工作的讲解者`、`为什么的综合者`、`反思的判断、发散和综合` 五行都用强模型。中仍是 1 到 2 项：两个系列都有就写 2 项，只有一个就写 1 项，推理 high。大是恰好 2 项，先快模型再强模型，推理 xhigh。不限至少 2 项，有第三个系列再加 1 项，不把同一个名字重复一遍来凑数，推理 max。宿主不能按次传模型时，评审组仍按这个项数写 `inherit-parent`，不改成空行。

3. **展示 18 行。** 必须把 18 行完整贴出来再问，不能只给汇总或数量。已有配置用 `write` 的只读预览保留角色值；只有用户明确选择全部重新分配时加 `--replace-roles`，修改单行用 `--set`。问是接受全部，还是改某一行。模型只能选已确认可派发名字、`inherit-parent` 或 `auto`，修改后重新展示。评审行数：省恰好 1 项且四行都在，中是 1 到 2 项，大恰好 2 项，不限至少 2 项。省不能把评审行改成空或删掉。跳过表示接受当前展示，仍不授权写入。

4. **确认后写入。** 展示完整标记段。用户同意才写。明确的「写入」「确认」才算同意；沉默、「随便」、「都行」只算跳过当前这步，不算同意，此时再问一次是否写入。写完说明路径、会不会自动读到、要不要新开对话。

## 用脚本生成、写入和校验

18 行由 [`scripts/s_models.py`](scripts/s_models.py) 按上面的规则生成，不要手工推导。命令用已有 Python 3，优先项目环境。脚本路径相对本技能目录，配置文件路径按宿主参考。

生成、预览与应用时都传 `--models <本次确认可派发的模型名，逗号分隔>`，在写入前校验全部角色。保留的旧角色使用了当前不可用型号时，先展示问题，由用户明确修改相关行。未提供此参数时脚本只做结构校验，不能证明型号可用。脚本不会联网探测模型。

- 第 3 步：首次配置用 `python scripts/s_models.py render --budget <省|中|大|不限|inherit-parent> --light <轻量模型> --fast <常规模型> --strong <复杂模型>`。已有配置改用 `write <配置文件> 同样的参数` 预览，默认保留角色值。Claude Code 加 `--role-effort`，派发时将括号内档位传给 `effort`；不限预算需要额外评审模型才加 `--third`；宿主不能按次传模型加 `--inherit`，这会明确将全部角色改成继承模式，展示变化并取得确认；宿主没有目标档加 `--effort <实际档>`，只能下调。用户改某一行用 `--set 角色=值`，可重复。脚本拒绝不合项数的改动，把错误原文告诉用户再问。预算改变导致保留的评审项数不合法时，请用户明确调整这些行或选择重新分配，不静默改写。
- 第 4 步：先跑 `write <文件> 同样的参数` 预览会做什么（create、append、replace 或 unchanged），用户明确同意后加 `--apply` 再跑一次。脚本只替换标记段，保留其他内容和换行风格，首次覆盖时留 `.s-models.bak` 备份；标记段不完整时拒绝写入。
- 写完跑 `check <文件> --models <这次确认的模型，逗号分隔>`，通过才说完成。日常只读自检也用 `check`。

Codex、Cursor、WorkBuddy 的模型名后缀先按宿主参考选定，再作为 `--light`、`--fast`、`--strong` 传入。轻量角色起始推理目标不高于 `medium`，再按模型实际支持的档位下调；不要给轻量模型套上全局高档后缀。显式角色档位优先。Cursor 的 frontmatter 和 Codex 的 toml 不归脚本管，仍按各自参考处理。

`# 预算` 写成 `省（medium）`、`中（high）`、`大（xhigh）`、`不限（max）`，宿主下调档位时括号里写实际档位，跳过则写 `inherit-parent`。旧行 `# budget` 以及 `small (medium)`、`medium (high)`、`large (xhigh)`、`unlimited (max)` 与这四档相同。重写时英文档名换成省、中、大、不限，括号里的档位照抄。

arena、architect、interrogate 按列表有几项就派几个。swarm、reflect、why、how 不读预算行来决定人数。这些技能认中文键，也认[角色键对照](references/role-keys.md)里的旧英文键。
