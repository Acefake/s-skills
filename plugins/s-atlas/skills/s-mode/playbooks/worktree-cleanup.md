### Worktree and simulator cleanup

先读取并遵守[执行边界](../references/execution-boundaries.md)。以下步骤仅在已有任务授权和验证档位内执行。

1. Snapshot and audit. Record disk usage with the platform's native command. Run `scripts/worktree-audit.sh [-b <pr-base-ref>] [repo-path]` only when its Bash, git, jq, and rg dependencies are available. On Windows use Git Bash or WSL for that script. Read actual worktree paths from `git worktree list --porcelain`; pass the real PR base instead of assuming origin/HEAD. Audit output is evidence, not deletion permission.
2. Confirm the authorized cleanup scope, exact absolute paths, ownership, and use. Cross-check active and pinned chats and their agent worktrees. Unknown ownership or usage means keep and report. Read only relevant transcripts. Delegate only when authorized and available; otherwise inspect sequentially.
3. Inventory every candidate's staged, unstaged, untracked, and ignored files. The script's `wip` and `scratch` counts are classifications, not proof that files are disposable. Show the affected files and preserve them unless the user has explicitly approved their loss. A merged branch does not recover uncommitted, untracked, or ignored content.
4. Remove only an authorized, unused worktree whose content has been handled. Use the host's archive tool for host-created worktrees. For a manually created Git worktree, verify that the resolved path is the intended target, leave that directory, and use `git worktree remove <verified-path>` without force. If removal fails, keep it and report why; do not retry with force, hard reset, git clean, or recursive deletion. Do not delete the current checkout or a path inferred from a directory name.
5. Re-list worktrees and confirm the actual result before reporting reclaimed space. Prune stale registrations only within the authorized cleanup scope. Keep branch refs unless branch deletion was separately authorized. A queued archive or failed removal is not a completed cleanup.
6. Treat simulators, package caches, IDE backups, and snapshots as separate user state. Inventory exact targets and impacts first. Delete only those covered by the user's cleanup request or subsequent explicit approval, using the platform's supported tools; do not clear everything the user did not specifically say to keep. On Windows verify resolved absolute targets remain within the explicitly named cleanup directory, and use one native shell end-to-end.

**Reply:** before/after disk usage with the actual command and scope, what was removed or archived, and each retained target with its reason. Do not claim unmeasured reclaimed space.
