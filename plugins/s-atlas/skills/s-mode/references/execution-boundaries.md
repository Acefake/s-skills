# 执行边界

所有 s-mode playbook 和子代理简报都遵守本页；具体步骤不能扩大已有授权。

- 先沿用用户已给的授权和限制，不重复询问。未授权的提交、推送、rebase、amend、PR 创建、合并、发布或清理不执行；保留工作区结果并报告。用户明确要求某项操作时，在该范围内执行，具体 Git 步骤按 commit-pr。点名 s-mode 或要求自主推进本身不授权上述操作。
- 团队聊天、工单写入、PR 评论及其他对外写入须有本次任务授权。未授权时交付消息或待办草稿。子代理不得取得超过父任务的授权。
- 只读调查和审查不改文件、不运行 no-comments 或 deslop 清理、不提交、不写外部系统、不运行测试。需要修复或补充验证时报告具体建议；用户已授权执行验证的任务另按对应验证档位处理。
- 技能来源在执行前记录实际插件根目录、清单版本及来源类型。计划、执行、定时复查和子代理使用同一来源；更换时先记录新路径和版本或已核实的仓库修订。不能假定目标项目的 trunk 包含技能库。
- 验证场景数量和证据形式按任务需要确定，跳过的检查注明原因。人工评审沿用用户已有要求；截图、视频和文档不是必须同时提供的材料，不额外增加审批关卡。
- 所有代码修改在交付前按 code-style 完成自审，覆盖完整任务差异和关键调用方，报告发现与未解决风险。小改动、不提交及不跑测试均不免除自审；清理、测试和独立评审不互相替代，按 code-style 风险条件默认委派只读独立评审，这不授权子代理实现或外部写入。明确禁止委派或工具不可用时报告缺口，不能以自审替代独立评审结论。
- 验证强度以 s-router 的分档为准，TDD 是否适用按 tdd。第0档只检查 diff，即使进入收尾或 PR 流程也不自动升级。复用同一代码上已有结果，未运行的检查明确标注。
- 保留已有暂存、未暂存、未跟踪和被忽略文件，不以 reset --hard、git clean 或强制删除作为同步、恢复和交接手段。已授权丢弃特定内容时，先确认对象、绝对路径、影响和可恢复性，只处理明确批准的对象。
- 工作区先确认来源、归属与使用状态。原生宿主创建的用原生工具管理；手工 Git worktree 才用 Git 清理。未知归属、仍在使用或有未处理文件时保留并报告，目录名和审计分类不能证明可删除。
