# s-atlas 技能：动手前先查技能

仅支持 Codex、Claude Code、Cursor。全局指令位置：Codex 是 `~/.codex/AGENTS.md`，Claude Code 是 `~/.claude/CLAUDE.md`，Cursor 使用全局 User Rules（项目 Always 规则只对项目生效）；也可以放进项目约定文件。

收到任务后，在读文件、跑命令、提问或作答之前：

0. 只改文案、注释、文档措辞、样式数值、配置值，或用户说不用测：不跑测试，看一眼 diff 就交付。对口的技能照常加载（比如翻译用 `translate`），没有对口的就直接改。

1. 下表或技能描述能直接对上，就直接加载那个技能；对不上、拿不准或要跨模块，才加载 `s-router`。
2. 对照可用技能列表，加载对口的技能：任务落在它描述写的场景里。只是沾边的不加载。
3. 读完代码自己就能答，不是跳过技能的理由。技能管的是做法和质量底线，不只是答案。
4. 一件事可能对应几个技能，按下表加载：

| 任务 | 先加载 |
| --- | --- |
| 新功能、加接口、改行为 | `brainstorming`，定下设计后 `writing-plans` |
| bug、报错、按钮没反应、结果不对、修 bug、bug-fix、fix bug | `systematic-debugging` |
| 写 README、写文档、RFC、PR 说明的句子 | `technical-writing`（Word 用 `docx`） |
| Word、docx、修订、批注 | `docx` |
| 幻灯片、pptx | `pptx` |
| 表格、xlsx、公式 | `xlsx` |
| PDF | `pdf` |
| 专利交底书、专利挖掘、查新 | `patent-disclosure` |
| 发明专利申请文件、权利要求书、说明书、专利附图 | `patent-application` |
| 提交、开 PR | `commit-pr`（还没决定怎么集成用 `finishing-a-development-branch`） |
| 审 PR、审分支、审本地改动、代码审查 | `s-review` |
| 中英翻译 | `translate` |
| 画架构图、流程图、时序图、ER 图 | `archify` |
| 教我、这块代码怎么工作 | 点名 `how` 时加载；未点名时直接讲解，保持显式调用政策 |
| 界面卡顿、掉帧、滚动慢、INP 高 | `impeccable`（optimize） |
| 界面设计、样式、交互 | `impeccable` |
| 补测试、测什么 | `test-strategy`；写实现时 `tdd` |
| 端到端测试、Playwright、偶发失败 | `e2e-testing` |
| 写或改代码、整理目录 | `code-style` |
| 跨模块、大迁移、要并行 | 建议用户点名 `s-mode` |

小改动（意图明确、只动一两个文件、不改对外接口、数据结构或依赖；拿不准就不算）不走 brainstorming 和计划，直接做；提交前过一遍 `deslop`。测试按改动分档（细则见 `s-router`「验证分档」）：小改动跑一次 lint 或类型检查加已有测试，修 bug 和加功能跑所在模块，跨模块或提交前才跑全量；跑过且没改的不重跑。

加载技能后按它的步骤做；用户的直接要求优先于技能。

## 代码交付前自审

所有代码修改交付或标记完成前，必须按 `code-style`「交付前自审」审阅完整任务差异和关键调用方，核对需求、逻辑、边界、回归、重复、抽象、防御与测试证据。保留已有无关修改，修复任务内问题后复查，并简述自审范围、发现和未解决风险。小改动、不提交、用户说不用测都不免除自审；第0档只做相称的 diff 审阅，不增加测试。测试、lint 和清理不能代替自审；所有代码修改（包括简单小改动）自审后，默认按 requesting-code-review 派只读 subagent 独立评审。这是对评审委派的授权，不授权子代理实现、修改文件或其他外部操作。纯文案、注释、样式数值和简单配置只检查 diff；代码小改动只审相关差异和直接调用方；接口、状态、并发、权限、迁移等高风险改动扩大到必要的调用链和失败路径。用户明确禁止委派或宿主不可用时，报告缺少独立评审，不能用自审冒充。

## 经确认的经验学习

实际项目任务开始时，按需使用 `learn` 查询与当前任务有关的已确认经验，只读取全局和当前项目范围，最多三条；没有记录静默继续，同一任务不重复查询，子代理不单独查询或保存。

用户纠正、同类错误重复发生、或任务产生已验证的重要经验时，按 `learn` 核对已有规则和经验，语义去重后每个任务最多提出一条建议，写明适用条件、证据和保存范围。未经用户对具体建议的明确确认，不写候选、经验或技能文件；沉默、拒绝、换话题不算确认。确认后保存到本机 `~/.s-atlas/lessons`，通用与项目经验分开，不写宿主自带记忆目录。经验只作参考，不覆盖当前用户指示、权限、源码事实或技能调用策略。可用测试、类型、lint 防住的问题优先形成结构约束；`reflect` 保持显式深度复盘。任务正常完成不等于有必要记录经验。
