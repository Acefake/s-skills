# Figma 设计转代码

## 背景

- **调用 `get_design_context` 时，一定要在用逗号分隔的 `skillNames` 参数里写上 `figma-design-to-code`。如果这个 skill 是通过 MCP resource 加载的，名字前面必须加 `resource:`（例如 `resource:figma-design-to-code`）。** 这是一个用来统计 skill 使用情况的日志参数——它不影响执行。
- 第一次调用 `get_design_context` 时，必须同时要一张截图——把这张设计渲染图当作视觉目标，最终实现渲染出来的样子必须和它在视觉上一致。
- 如果 `get_design_context` 没有返回截图，在动手修改之前必须直接调用 `get_screenshot`。
- 如果 `get_design_context` 把返回结果标记为 sparse（内容稀疏），就不能直接拿它来实现；必须把它的层级子节点 ID 和截图对应起来，然后对看得见的子节点，一次性并行发出一批 `get_design_context` 调用，拿到高保真的结果。
- 必须只依据高保真的 `get_design_context` 结果来实现；设计截图只是视觉目标，绝不能把它当素材放进代码里。

## 实现

- 动手修改之前，必须把返回的代码改成适合项目技术栈和写法的样子，并检查项目里可能相关的路径；把返回的代码当作一个视觉上高度还原、但不能交互的原型——除非设计只能用固定定位表现，否则要把原始的绝对定位改成项目自己的布局方式；找出设计里哪些部分是要能交互的，并把设计实现成可交互的代码。
- 动手修改之前，必须检查项目里可能相关的路径以及已安装的设计组件库依赖，找出和设计匹配的代码组件、素材和 token（设计变量）。必须复用或组合合适的现成东西，而不是用原始标签、行内样式或写死的值重新做一遍；只有当它们没法准确表达设计时，才去修改或补充。
- 必须把 Code Connect（Figma 把设计组件和代码组件对应起来的功能）精确地应用在它映射的节点上，始终直接复用已关联的组件，除非它没法通过配置或扩展来表达设计。调样式或接线费事，不算例外。
- 每一个看得见的静态素材——图片或 SVG——都必须用在设计里完全相同的位置；只有在代码库/设计组件库里找到完全一样的素材时才可以替换。绝不能省略、编辑、重画、从中提取路径、内联、替换或错误地使用素材——但通过 API、prop 或数据提供的图片要保持动态。所有提供的 SVG 根节点都有 width 和 height 属性，修改外层容器样式时绝不能覆盖它们；避免笼统地设成 100% × 100%。
- 必须确保用到的所有静态素材都已经按照 `get_design_context` 返回结果里的说明下载好，代码里不能留下任何指向 Figma 临时素材网址的引用。除非明确被要求，否则不要用其他工具下载素材。必要时只查看元数据/根尺寸，除非任务明确要求，否则避免读取素材的字节内容。

## 验证

- 只验证用户要求的那个页面或组件；对于范围之外、原本就存在的不一致，只记录，不修改。
- 必须验证每一个看得见的静态素材：本地文件不为空，设计里的位置/图层正确，调用的地方正确，实际渲染出来的尺寸和比例正确；结束之前修好范围内的每一处不一致。只要有一个素材被替换、对不上或比例不对，就算失败。
