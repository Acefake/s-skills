# 依赖检查和升级

## 检查

1. 用项目自己的包管理器：看锁文件判断是 npm、pnpm、yarn、Go modules、Maven 还是 Gradle，不要换工具。
2. 先查安全公告（如 `npm audit --json`、`pnpm audit`、`govulncheck ./...`），再查过期版本（如 `npm outdated`、`go list -m -u all`）。
3. 分组，按这个顺序排：
   - **安全修复**：有公告且有修复版本的。写上严重程度和公告编号。
   - **大版本**：读它的更新日志，列出会影响本项目的破坏性变更。
   - **小版本和补丁**：可以合成一个 PR 的放一组。
4. 只用到开发环境的依赖单独标出，它们通常不急。

## 升级（主人同意后）

1. 每组派一个 worker，在新工作区里升级。只动这一组，锁文件一起提交。
2. 跑项目已有的构建、类型检查和测试。挂了就修；修不好就在 PR 里写清楚卡在哪，不要跳过测试。
3. PR 描述写明：升了什么、为什么、破坏性变更怎么处理的、测试结果。

## 回报格式

```text
安全修复（1）
- http-client 6.19 → 6.21：高危，GHSA-xxxx，修复请求走私
大版本（1）
- test-runner 2 → 3：配置文件改名，影响 3 个文件
小版本（4）：可合成一个 PR
要我开哪几组？
```
