# 发版就绪检查

## 步骤

1. 从记忆里读发版分支，以及标记阻塞用的标签或里程碑。没有记录就问主人，问到后写进记忆。
2. 查三类，每项都附链接：
   - **检查**：发版分支最新提交上失败或卡住的检查（`gh run list --branch <分支>`）。
   - **PR**：进了这次里程碑、还没合并的 PR，写明卡在审查、检查还是冲突。
   - **阻塞**：带阻塞标签、还开着的 issue。
3. 每项写上负责人：PR 作者、指派人，或者最近一次提交的人。
4. 和上一次清单比较，标出新增和已解决的。

## 回报格式

```text
发版 <版本或里程碑>：还差 3 项
检查（1）
- build-windows 在 abc1234 上失败：<链接>，负责人 @xxx
PR（1）
- #812 等审查 2 天：<链接>，作者 @yyy
阻塞（1）
- #790 升级后启动崩溃：<链接>，指派 @zzz
比昨天：新增 1，已解决 2
```

三类都清空时，只回一句“可以发版”，附发版分支的最新提交。只看不动：不打 tag、不合并 PR、不改里程碑。
