# 先复现，再找根因

## 步骤

1. 从报告里摘出：预期是什么，实际是什么，在哪个环境、哪个版本。缺了会影响复现的信息，先问主人。
2. 派 worker 在新工作区里复现。写下最短的复现步骤：命令、输入、看到的输出。复现不了就如实说，列出试过的条件，不猜原因。
3. 从症状往回追，找到系统第一次算错或状态第一次不对的地方。每一步都要有证据：日志、断点输出、一个能失败的测试。
4. 同一个前提下修了两次都不对，停下来，直接验证这个前提。
5. 提出修法。修在根因处，不在症状处加判断。说明会影响哪些调用方。

## 回报格式

```text
复现：能 / 不能
步骤：
1. ...
根因：path/to/file.go:88 <哪里第一次出错，为什么>
证据：<日志、测试或输出>
修法：<改哪里、怎么改、影响谁>
要我开始修吗？
```

主人同意之前不改代码、不开 PR。修的时候先写一个会失败的回归测试，修好后它要通过。
