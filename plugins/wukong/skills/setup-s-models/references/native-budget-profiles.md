# 原生宿主：按能力动态选模（省 / 中 / 高 / 超高）

只在当前工具能派发本厂商模型、没有已授权跨提供商编排能力时使用本文件。T3 中存在可用跨提供商工具时优先用 `t3_catalog.py plan` 或[混合方案](mixed-budget-profiles.md)。环境由实际工具与目标能力决定，不仅看父模型或应用名称。

**严禁写死具体型号或版本号。** 先实测发现当前宿主实际可用的模型列表、思考参数和已有角色文件，按三类能力定位动态取**当前可用最新一代**：

- **轻量档（Light）**：速度最快、成本最低的轻量/快模型（用于高频只读检索）。
- **主力档（Balanced）**：代码质量与速度均衡的主力编码模型（同档有新版本时永远优先最新代）。
- **旗舰档（Heavy）**：推理上限最高的旗舰模型（仅在高杠杆角色或充裕订阅时启用）。

## 四档预算 × 订阅额度动态映射

每格为「首选 → 次选（同宿主有第二可用模型时）」，一次只启动一个。若当前订阅为**入门/紧张（`low`）**，「省」档**禁止分配旗舰档**，表中旗舰档自动降为「主力档 + `medium`/`high`」；若单家且入门订阅强选「高 / 超高」，须先提示限流风险。

| 角色 | 省 | 中 | 高（工具预算“大”） | 超高（工具预算“不限”） |
| --- | --- | --- | --- | --- |
| 检索与探索 | 轻量 `low/medium` → 主力 `low` | 轻量 `medium` → 主力 `medium` | 轻量 `medium` → 主力 `medium` | 轻量 `medium` → 主力 `medium` |
| 方案设计 | 主力 `medium` → 旗舰 `medium` | 主力 `high` → 旗舰 `medium` | 旗舰 `medium/high` → 主力 `high` | 旗舰 `high/max` → 主力 `high` |
| 开发实现 | 主力 `medium` → 旗舰 `medium` | 主力 `high` → 旗舰 `medium` | 主力 `high` → 旗舰 `medium` | 旗舰 `high` → 主力 `high` |
| 专项攻坚 | 旗舰 `medium`（入门池降为主力 `high`）→ 主力 `high` | 旗舰 `high` → 主力 `high` | 旗舰 `high` → 主力 `high` | 旗舰 `max/xhigh` → 主力 `high` |
| 验证测试 | 主力 `medium` → 轻量 `medium` | 主力 `medium` → 旗舰 `medium` | 主力 `high` → 旗舰 `medium` | 主力 `high` → 旗舰 `high` |
| 独立评审 | 主力 `medium`，1 名 | 主力 `medium`，1 名 | 名额 1 主力 `medium`；名额 2 旗舰 `medium`，共 2 名 | 名额 1 旗舰 `high`；名额 2 旗舰 `max/xhigh`，共 2 名 |

## Codex 原生

按当前 Codex 会话实测可用的模型列表动态填入轻量档、主力档、旗舰档，**不写死版本号**。若 `~/.codex/agents/*.toml` 中已有角色文件绑定了旧代模型，在预览变更时主动标明当前最新可用代并询问是否同步升级。

有固定模型的自定义角色时，为首选与次选选择各自匹配的已发现角色，不能用旧角色冒充未配置的模型，也不能在备用触发时临时重写角色文件。原生工具不能逐次指定模型或推理档位时，使用实际支持的匹配角色，否则明确报告继承父会话及未分流；不模拟跨提供商调度。

继承只适用于用户允许继承或正在确认候选方案的情形；执行已指定模型的任务时，缺少匹配角色就报告目标不可用，不能静默改为继承或其他型号。

## Claude Code 原生

按当前 Claude Code `Agent` 工具实际接受的模型取值（别名或实测可用 ID）动态填入轻量档、主力档、旗舰档，不把 T3 完整 ID 或带括号的字符串传入 `model`。参数以当前 `Agent` 定义为准：存在独立 `effort` 字段才按其合法值传入；不存在时报告实际继承或无法设置，不伪造已指定推理档位。不能借 shell 启动别家 CLI 来填补原生宿主能力。

## 配置与运行

1. 先探测当前宿主实时可用模型、参数和已有配置，再确认作用域、订阅额度与省/中/高/超高预算；用户已有配置或明确自定义时按其确认结果展示。一次展示六角色、每个名额的首选/次选、参数和人数。
2. 现有脚本把各名额首选写入角色行，逗号仍表示独立名额；备用顺序不写成逗号模型列表。明确的角色档位优先于通用预算映射，不机械拉满到 `xhigh`/`max`。
3. 项目级持久化备用时，预览 `docs/project/s-model-fallbacks.md` 和该宿主真正读取的规则文件中的入口（Codex 为 `AGENTS.md`，Claude Code 为 `CLAUDE.md`），最终确认后写入并回读。
4. [顺序备用规则](mixed-budget-profiles.md#首选失败后的操作)同样适用：明确不可用才切换已授权次选，先停止并对账旧任务，单个候选最多尝试一次，失败后报告受阻。配额或提供商整体不可用时，同厂商备用不保证有效。
5. 高/超高档两个评审名额必须使用独立会话；单家原生宿主缺乏跨厂商视角时明确说明。
