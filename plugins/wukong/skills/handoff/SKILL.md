# 跨会话交接

把当前未完或刚告一段落的任务，压缩成下一会话（或换另一个宿主）能直接接手的紧凑交接文档。只写核实过的事实，不写推测。

## 先取真实证据

在动笔前，只读检查当前工作区（如果当前目录是 git 仓库）：

- 当前分支名与 `HEAD` 完整或短提交号（`git rev-parse --abbrev-ref HEAD`、`git rev-parse --short HEAD`）
- 未提交改动清单（`git status -s`）
- 本会话实际跑过且能引用的验证命令和结果

不要凭记忆编造提交号、文件路径或测试结果；没跑过的验证明确标「未跑」。

## 交接结构

按以下 5 节输出，尽量精炼，总长度控制在下一会话一眼能读完的体量：

1. **目标与边界**：用户要达成什么、明确不做哪些事、已敲定的关键决策。
2. **当前状态与已验证证据**：仓库路径、分支、`HEAD` SHA、工作区未提交文件；已完成事项及对应的实际命令/测试结果。
3. **未完成与下一步**：按顺序列出剩余事项，每项写清涉及的文件和完成判据。
4. **踩过的坑与约束**：已经试错排除的路径、环境/平台限制、不能碰的边界，避免下一会话重踩。
5. **下一会话接续提示词**：放进一个单独的 fenced 代码块，自包含、可直接复制粘贴给新会话执行（含目标、仓库/分支状态、下一步动作与验收标准）。

## 输出规则

- **默认直接输出在对话中**；遇到即将 `/compact` 或 `/clear`、担心有损压缩丢关键信息时，可写入工作区临时 `HANDOFF.md`（不加入 git 提交，下一会话接手确认后即删）；用户指定了其他路径时以指定路径为准。
- **不放敏感信息**：绝不写入密钥、token、密码、Cookie 或个人隐私内容。
- **用指针代替粘贴**：代码和日志只写文件路径、行号或关键结论，不大段拷贝原文。
- 如果任务已有正在维护的计划文档或项目记录，直接链接到对应路径，不重复抄写全文。
- 职责分工：项目级长期现状与术语优先沉淀到 [project-memory](../project-memory/SKILL.md)，跨项目个人偏好与技能改进用 [reflect](../reflect/SKILL.md)，本技能只负责当前会话到下一会话的即时交接。
