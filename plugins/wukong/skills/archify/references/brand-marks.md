# 品牌标志

只有当一个真实的产品、提供方、模型家族、渠道或服务身份对读者有帮助时，才使用品牌标志。语义 `type` 仍然说明节点做什么；`brand` 说明它是谁的产品。

## 代理决策路径

1. 当请求提到一个可识别的品牌时，搜索内置目录：

   ```bash
   node bin/archify.mjs brands "Claude" --json
   ```

2. 把返回的规范 ID 放进节点、参与者或状态中：

   ```json
   {
     "id": "planner",
     "type": "backend",
     "label": "Claude",
     "brand": "claude"
   }
   ```

3. 如果目录中没有匹配，而用户提供了官方网站，就显式抓取它的图标：

   ```bash
   node bin/archify.mjs brands capture "https://partner.example.com" --json
   ```

   把该命令返回的、以摘要固定的 `brand` 值放进编写的节点中：

   ```json
   {
     "id": "partner",
     "type": "external",
     "label": "Partner portal",
     "brand": {
       "url": "https://partner.example.com",
       "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
     }
   }
   ```

4. 如果没有匹配，也没有用户提供的 URL，就省略 `brand`。不要编造 URL，也不要悄悄指定一个看起来相似的公司。

已知品牌的 URL 解析为内置的矢量图，而不使用网络。对于发现的图标 `href` 属性，抓取会在 URL 解析之前，对基本命名引用 `amp`、`quot`、`apos`、`lt`、`gt`（及其已定义的大写别名）以及十进制和十六进制数字引用解码一次。因此 `/icon.png?v=1&amp;size=32` 请求的是 `/icon.png?v=1&size=32`。URL 百分号转义保持不变；嵌套的转义不会被递归解码。这个有界解码器不会引入通用 HTML 解析器，也不支持所有 HTML 命名实体。HTML 读取在位于注释、原始文本元素和带引号属性之外的显式 head 结束处停止，包括这些标记跨越网络分块的情况。256 KiB 的 head 上限和抓取截止时间仍然适用；head 之后更大的正文不会为发现图标而读取。图标候选来自注释、原始文本和 template 内容之外的完整 `link` 标签。属性值和 `data-href` 这类形似的名称不能提供图标声明；带引号的 `>` 字符留在其标签之内。对于 `text/html`，发现过程把 `noscript` 内容视为原始文本，与启用脚本的 HTML 解析一致；抓取不执行脚本。这一排除不适用于 `application/xhtml+xml`，其中的 `noscript` 链接仍可被发现。`<script />` 和 `<template />` 这样的 XHTML 空元素不会隐藏后面的链接；同样的结尾斜杠在 `text/html` 中不会关闭这些元素。未知 URL 的抓取只接受有界的光栅图像格式，阻止凭据、非标准公共端口以及私有或链路本地目标，使用有界并发和单一总截止时间，并返回抓取内容的摘要。之后的渲染和校验操作都要求这个确切的摘要；被阻止、不可用、已改变、超大或不安全的内容会以失败关闭，而不是悄悄改变产物。

抓取回执、节点元数据和 SVG/HTML 中的远程品牌来源信息，保留源 URL 的 HTTP(S) scheme、主机、端口和路径，但省略 userinfo、查询字符串和片段。编写的 `brand.url` 以及所有下载/重定向 URL 保持不变，因此已有的固定值仍能复现相同的字节和摘要。携带凭据的下载 URL 仍会被拒绝。内置标志保留其记录的目录来源信息。

公开的源链接标识的是原始站点/路径，不一定是可下载的资源：移除带签名的查询或基于查询的页面选择器，可能使该链接不可用或不够具体。当有可用的稳定公开落地页并暴露了目标图标时，优先抓取它；不要在没有重新抓取和验证来源的情况下编辑已有固定值的 URL。路径会被保留，所以这种规范化并不是通用的 URL 机密清除器。

从一个曾抓取非活动 HTML 标记（包括 `noscript`）的版本升级后，已有的 URL 固定值可能因 `brand/digest-mismatch` 而失败，因为发现过程现在选中了另一个图标。检查目标图标，对同一 URL 重新运行上面的抓取命令，然后用返回的固定值显式替换编写的 `brand` 值。已有固定值不会被自动改写，摘要验证仍然强制执行。

对于 ICO 抓取，每个目录条目都必须引用一个位于完整目录之后、且在已下载文件之内的非空图像范围。复现一个已固定的抓取时也会应用这个边界检查。PNG/DIB 载荷、多张图像、共享或乱序的范围以及尾部字节仍受支持；该检查不解码像素，也不保证一个在其他方面有界的载荷可以解码。一个被拒绝的 ICO 候选不会妨碍尝试后面的图标。

页面、图标和重定向请求发送 `Accept-Encoding: identity`。抓取不解压响应正文：一个声明了其他内容编码的成功响应会被关闭并被明确拒绝。这让已有的字节上限和固定摘要绑定在未编码的表示上。后面某个可用的图标仍可能成功；否则会保留编码错误，而不是被一个无关的 favicon 404 掩盖。

最终产物在打开时绝不会抓取品牌资源。预设矢量图和经摘要验证的已抓取站点图标，会保持嵌入在 SVG、PNG、WebP、JPEG、Share Card 和 WebM 导出中。

使用 `node bin/archify.mjs brands --json` 查看所有规范 ID、别名、类别、域名和来源信息。当前类别涵盖 AI、云、工程、数据、协作、业务系统、渠道、语言和框架。
