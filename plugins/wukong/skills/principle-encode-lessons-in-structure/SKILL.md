# 把教训写进结构

同一类错误再次出现时，找出能由工具或结构持续保证的规则，避免每次靠人记住提示。

## 做法

1. **写清重复错误。** 列出已经发生的实例、共同原因和必须成立的不变量，避免把单次实现细节变成通用禁令。
2. **选最窄的约束位置。** 优先现有类型、数据结构、解析边界、lint、测试或CI；能从源头使错误无法表示，就不再增加平行校验。
3. **实现检查或结构约束。** 复用已有工具，明确覆盖范围和失败信息，不为一个规则引入整套框架。
4. **验证有效性。** 一个真实违规例子应被拒绝，正常例子应通过；说明它如何抓住之前的错误。
5. **放到持续生效的位置。** 接入项目实际使用的类型检查、构建或CI入口，记录文件和执行方式，删除被等效替代的重复提示。

如果规则依赖判断、无法写成结构，把指示放到使用者会看到的位置，并附失败例子与判断依据；不要声称已经自动防住。

**完成标准：** 说明现在由什么约束保证什么、怎样验证、仍需人判断什么。结构性修复本身足够时，不再叠加只重复同一要求的提醒。
