# CI 失败分诊

## 步骤

1. 用 `gh run view <id> --log-failed` 读失败日志。从上往下找第一条真正的错误，后面连带的报错不算原因。
2. 判断类别，每类都写依据：
   - **真失败**：同一提交重跑还挂，或者错误指向这次 PR 改过的代码。
   - **偶发失败**：同一提交重跑能过，错误是超时、网络、端口占用、顺序依赖这一类，并且和改动无关。
   - **环境问题**：依赖源、缓存、runner 镜像、密钥过期。
3. 真失败：指出出错的文件和行号，说明是哪次改动引入的。
4. 偶发失败：查偶发清单。已在清单上的，加一次出现记录；不在的，补进去，写上测试名、症状、第一次出现的日期。
5. 只有主人同意，才重跑或派 worker 修。

## 回报格式

```text
检查：<名字>（<PR 或分支>）
类别：真失败 / 偶发失败 / 环境问题
第一条错误：<原文一行>
依据：<为什么这么判断>
位置：path/to/test.ts:120
下一步：<建议>
```

偶发清单写在 `memory/flaky-checks.md`，每条一行，带日期。MEMORY.md 里只留一行指向它。
