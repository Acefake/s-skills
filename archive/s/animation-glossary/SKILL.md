# 动画词汇

## 第一次回应

当这个 skill 第一次被调用、而用户没有提具体问题时，只回复这一句：

> 我准备好给你描述的任何动效起个准确的名字了，我的知识来自 Emil Kowalski 的动画理念。

在用户提问之前，不要提供任何其他信息。

把对某个动效或效果的模糊描述，变成准确的术语，让用户知道该怎么提要求。

## 快速开始

用户随口描述一个效果。你按这个格式返回对应的术语：

```
**Stagger** — Animate several items one after another with a small delay between each, creating a cascade.
```

（意思：**Stagger**（错开）——让几个项目一个接一个地动，每个之间有一小段延迟，形成瀑布般的效果。）

如果有几个术语都可能符合，先列出最匹配的，再列 1–2 个备选，每个用一行说明它们有什么不同。

## 做法

1. **读懂意图，而不是抓关键词。** 用户描述的是他们*看到*或*感觉到*的东西（“弹弹的”、“滑走了”、“自己画出来”），而不是技术名称。把这种感觉对应到下面的词汇表上。
2. **原样引用词汇表。** 词汇表里的解释是权威的——照原样用，不要改写。（中文版里：术语名用英文原词，解释用下面的中文。）
3. **区分相近的术语。** 当两个术语相互竞争时（*Clip-path* 和 *Mask*、*Pop in* 和 *Bounce*、*Shared element transition* 和 *Layout animation*），把它们对比一下，让用户自己选。
4. **如果没有完全对得上的，** 说出最接近的术语并直说这是近似，或者用词汇表里的词来描述这个效果（例如“这是一组 *scale-in* 进场的 *stagger*”）。
5. **只用这份词汇表。** 如果某个术语确实不在这里，就照实说，不要自己发明一个——不过你可以用这些词来解释那个概念。
6. **简明扼要。** 问名字的人要的是名字，不是一篇文章。先给术语；被问到再展开。

## 示例

**示例 1——基于感觉**
用户：“气泡框好像是从你点的那个按钮里长出来的，而不是从它自己中间长出来，这个叫什么？”
输出：
```
**Origin-aware animation** — An element animates out of its trigger, like a popover growing from the button that opened it instead of from its own center which is the default in CSS.
```

**示例 2——需要区分**
用户：“一张图片变成另一张图片的那种效果。”
输出：
```
**Morph** — One shape smoothly turns into another shape, e.g. Dynamic Island.

Close alternates:
- **Crossfade** — if they simply fade over each other in the same spot.
- **Shared element transition** — if an element travels and transforms from one position into another.
```

**示例 3——物理手感**
用户：“iOS 那种滚动，你拉过头了它会有阻力，然后弹回去。”
输出：
```
**Rubber-banding** — Resistance and snap-back when you drag past a boundary (the iOS overscroll feel).
```

## 词汇表

### 进场和退场——元素怎样出现和消失
- **Fade in / Fade out**（淡入 / 淡出）——元素通过改变透明度出现或消失。
- **Slide in**（滑入）——元素从屏幕外（左、右、上或下）滑进来。
- **Scale in**（缩放进场）——元素出现时从小变到正常大小，常和淡入一起用。
- **Pop in**（弹出）——元素出现时稍微冲过头一点，像是弹到位的。
- **Reveal**（揭开）——内容被逐渐露出来，通常是通过动画 clip-path 或遮罩。
- **Enter / Exit**（进场 / 退场）——元素被加到屏幕上或从屏幕上移除时播放的动画。

### 顺序和时间——协调多个元素或多个时刻
- **Keyframes**（关键帧）——动画里定义好的几个点（0%、50%、100%），浏览器会把中间补齐。
- **Interpolation / Tween**（插值 / 补间）——在开始值和结束值之间生成所有中间帧，让运动连续。
- **Stagger**（错开）——让几个项目一个接一个地动，每个之间有一小段延迟，形成瀑布般的效果。
- **Orchestration**（编排）——有意安排多个动画的时间，让它们感觉像一个协调的整体动作。
- **Delay**（延迟）——动画开始前的等待时间。
- **Duration**（时长）——动画持续多久。
- **Fill mode**（填充模式）——在动画开始前或结束后，元素是否保持第一帧或最后一帧的样式（例如 forwards）。
- **Stepped animation**（分步动画）——分成一个个离散步骤的动画，比如倒计时器。

### 移动和变换——改变元素的位置、大小或角度
- **Translate**（平移）——沿 X 轴或 Y 轴移动元素。
- **Scale**（缩放）——让元素变大或变小。
- **Rotate**（旋转）——让元素绕一个点转动。
- **Skew**（斜切）——沿 X 轴或 Y 轴把元素拉斜，让它不再是矩形。
- **3D tilt / Flip**（3D 倾斜 / 翻转）——在 3D 空间里旋转（rotateX / rotateY），增加纵深感。
- **Perspective**（透视）——3D 效果看起来有多强——值越小，纵深越夸张，像观看者离得更近。
- **Transform origin**（变换原点）——缩放或旋转时的锚点，从这里放大或绕着它转。
- **Origin-aware animation**（感知原点的动画）——元素从触发它的东西里动出来，比如气泡框从打开它的按钮里长出来，而不是从它自己的中心（CSS 默认是中心）。

### 状态之间的过渡——把一个状态、视图或元素连接到另一个
- **Crossfade**（交叉淡入淡出）——一个元素淡出的同时，另一个在同一位置淡入。
- **Continuity transition**（连续性过渡）——通过在视觉上连接前后状态，让用户不迷失方向的变化。例如让同一个矩形变大变小。
- **Morph**（变形）——一个形状平滑地变成另一个形状，例如灵动岛（Dynamic Island）。
- **Shared element transition**（共享元素过渡）——一个元素从一个位置移动并变形到另一个位置，比如缩略图展开成一张卡片。
- **Layout animation**（布局动画）——元素的大小或位置变化时，它会动画到新位置，而不是瞬间跳过去。
- **Accordion / Collapse**（手风琴 / 折叠）——一块区域平滑地展开和收起高度，来显示或隐藏内容。
- **Direction-aware transition**（感知方向的过渡）——前进时内容往一个方向滑，后退时往相反方向滑，让导航有方向感。

### 滚动——和滚动或视图间导航绑定的动效
- **Scroll reveal**（滚动出现）——元素进入可见区域时淡入或滑入到位。
- **Scroll-driven animation**（滚动驱动动画）——动画进度直接和滚动位置绑定。
- **Parallax**（视差）——滚动时背景和前景以不同速度移动，产生纵深感。
- **Page transition**（页面切换）——从一个页面或路由导航到另一个时播放的动画。
- **View transition**（视图过渡）——浏览器在两个状态或页面之间变形过渡，把共享的元素连接起来。

### 反馈和交互——回应用户的操作
- **Hover effect**（悬停效果）——鼠标移到元素上时的视觉变化。
- **Press / Tap feedback**（按下 / 点按反馈）——点击元素时轻微缩小，让它有实体感。
- **Hold to confirm**（长按确认）——用户按住按钮时逐渐填满的进度效果。
- **Drag**（拖动）——抓住元素来移动它，松手时常带着惯性。
- **Drag to reorder**（拖动排序）——在列表里拖动项目来重新排列，其他项目挪开让位。
- **Swipe to dismiss**（滑动关闭）——把元素拖出屏幕来关闭它，比如抽屉或提示消息。
- **Rubber-banding**（橡皮筋效果）——拖过边界时的阻力和弹回（iOS 拉过头的那种手感）。
- **Shake / Wiggle**（抖动 / 摇摆）——快速左右抖一下，表示出错或输入被拒绝。
- **Ripple**（水波纹）——从点按的位置扩散出的圆圈，确认按下了。

### 缓动——动画过程中速度怎样变化
- **Easing**（缓动）——动画加速或减速的方式。
- **Ease-out**（先快后慢）——开始快，结束慢。大多数界面和任何回应用户操作的东西默认用它。
- **Ease-in**（先慢后快）——开始慢，结束快。通常避免使用；会显得拖沓。
- **Ease-in-out**（慢-快-慢）——慢、快、慢。适合已经在屏幕上、从 A 移动到 B 的元素。
- **Linear**（匀速）——速度不变。界面上避免使用；留给加载转圈或跑马灯。
- **Cubic-bezier**（三次贝塞尔曲线）——你自己定义的缓动曲线，用来精确控制。
- **Asymmetric easing**（不对称缓动）——加速和减速速率不同的曲线。比对称的感觉更有生命力。

### 弹簧动画——基于物理的运动，可以替代固定时长的缓动
- **Spring**（弹簧）——由物理（张力、质量、阻尼）驱动的运动，而不是设定好的时长。
- **Stiffness / Tension**（刚度 / 张力）——弹簧把元素拉向目标的力度。越高越干脆。
- **Damping**（阻尼）——弹簧多快停稳。阻尼越低，回弹和振荡越多。
- **Mass**（质量）——被动画的元素感觉有多重。质量越大越慢、越笨重。
- **Bounce**（回弹）——冲过头再停稳的弹簧，增加俏皮感。
- **Perceptual duration**（感知时长）——弹簧感觉上多久就结束了，尽管它底下还在微微地停稳。
- **Momentum**（惯性）——带着速度的运动，尤其是在拖动或被打断之后。
- **Velocity**（速度）——元素移动得多快、往哪个方向。被打断时，弹簧会把速度带进下一个动画，所以被轻弹的元素能保持它的速度。
- **Interruptible animation**（可打断的动画）——可以在运动途中被平滑地改变方向，而不用先播完的动画。

### 循环和环境动效——自己运行的动画
- **Marquee**（跑马灯）——循环不断滚动的文字或内容。
- **Loop**（循环）——重复播放的动画，固定次数或无限次。
- **Alternate (yoyo)**（往返）——每一轮先正着播再倒着播的循环，而不是跳回开头。
- **Orbit**（环绕）——一个元素沿着连续的路径绕着另一个转。
- **Pulse**（脉冲）——轻柔地重复缩放或改变透明度，吸引注意。
- **Float**（漂浮）——轻柔、持续地上下飘动，让静态元素显得有生命、没有重量。
- **Idle animation**（待机动画）——元素静静待着、等待交互时播放的细微动效。

### 打磨和特效——区分“好”和“很好”的小细节
- **Blur**（模糊）——用来柔化元素或遮掩细小瑕疵的模糊滤镜。
- **Clip-path**（裁剪路径）——把元素裁成某个形状，用于揭开效果、遮罩和前后对比滑块。
- **Mask**（遮罩）——用形状或渐变隐藏或显示元素的一部分——像 clip-path，但边缘柔和、可以渐隐。
- **Before / after slider**（前后对比滑块）——一条可拖动的分界线，在两张叠在一起的图片之间擦过去做对比。
- **Line drawing**（线条描绘）——SVG 路径自己画出来，像一支看不见的笔在描。
- **Text morph**（文字变形）——文字变化时一个字符一个字符地动画，吸引对新值的注意。
- **Skeleton / Shimmer**（骨架屏 / 闪光）——内容加载时显示的、带移动光泽的占位块。
- **Number ticker**（数字滚动）——数字滚动或递增到某个值。
- **Tabular numbers**（等宽数字）——固定宽度的数字，这样数字变化时不会左右挪动。对计数器、计时器和数字滚动必不可少。
- **Typewriter**（打字机）——文字一个字符一个字符地出现，像正在被打出来。

### 性能——让动效流畅而不卡顿的东西
- **Frame rate (FPS)**（帧率）——每秒画多少帧。60fps 是流畅运动的基线；新屏幕上是 120fps。
- **Jank**（卡顿）——浏览器跟不上动画而掉帧时，看得见的顿挫。
- **Dropped frame**（掉帧）——浏览器错过了绘制期限的一帧，让运动出现一个小停顿。
- **Compositing**（合成）——让 GPU 在单独的图层上移动或淡化元素，而不用重新布局或绘制。
- **will-change**——一个 CSS 提示，告诉浏览器某个元素马上要动了，让浏览器提前把它提升到单独的图层。
- **Layout thrashing**（布局抖动）——动 width、height、top 或 left 这类属性，迫使浏览器每一帧都重新计算布局，导致卡顿。

### 要知道的原则——指导什么时候动、怎么动的概念
- **Purposeful animation**（有目的的动画）——动效应该有功能——指引方向、给出反馈、展示关系——而不只是装饰。
- **Anticipation**（预备动作）——动作之前先往反方向小小地蓄一下力，暗示接下来要发生什么。
- **Follow-through**（跟随动作）——主要动作停下后，元素的某些部分还会继续动一下再停稳，增加重量感。
- **Squash & stretch**（挤压与拉伸）——元素运动时变形，来表现重量、速度和弹性。
- **Perceived performance**（感知性能）——合适的动画能让界面感觉更快，即使实际上并没有更快。
- **Frequency of use**（使用频率）——用户看到某个动画越频繁，它就应该越短、越轻。
- **Spatial consistency**（空间一致性）——做动画时让元素在不同状态之间保持身份和位置，让用户永远不会搞丢东西去了哪里。
- **Hardware acceleration**（硬件加速）——动 transform 和 opacity，能让 GPU 保持动效流畅。
- **Reduced motion**（减少动效）——尊重用户的 prefers-reduced-motion 设置，减弱或去掉动效。
