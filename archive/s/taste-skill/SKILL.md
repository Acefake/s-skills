## 运行环境适配

在 Codex 或 T3 Code 中，执行前先阅读[宿主适配规则](../../../plugins/s/HOSTS.md)；其中的模型、委派、浏览器和定时任务规则优先于下文的 Cursor 专用示例。


# 前端设计品味

这是 tasteskill v2。模型做出来的页面，通常是它见过的所有页面的平均数：居中的大标题排成三行，上面再放一个小标签，
下面一排图标卡片，一层柔渐变，几条细线，再加一行等宽字体的小说明。里面没有一样是错的，
也没有一样是定下来的。

这份技能用决定换掉这些默认，一共四件事：

1. **脚本发方向，你来挑。** 让模型自己发明一个样子，它每次都选这个品类的默认款。
   `scripts/draw.mjs` 从二十个研究过的方向里发三张。你挑那个能托住题材点子的。
   脚本再从资料库里发它的字体系统（type system）、配色（palette）、
   首屏（hero）和各区块的构图（composition）。这库是从 247 个真站点里提炼的。
2. **点子从题材本身来。** 研究里，最好的站和让人忘掉的站，差在点子是从这件东西本身取的，
   不是从样式上取的。
3. **一套不带装饰的本家风格（house style）。** 用 `scripts/inspect.mjs` 在真浏览器里量。
   规矩是查出来的，不是指望着的。
4. **你要看自己做出来的东西。** 三个宽度的截图，一张评审打分表，改，再看。

测试里学到的一句警告。把装饰拿掉，只做了一半。页面丢了小标签、细线和卡片，原地又没补上东西，
读起来就薄。盲评的人有道理：他们宁可要一页更满、带着破绽（tell）的，也不要一页空的、
没有破绽的。另一半是分量：字排得更大，整片的色块，
这个题材自己世界里的真图（找到的，或画出来的），每个区块都装着完整内容。
这份技能就是为了把这些给你。别拿克制把它们换掉。

下面命令里的 `<skill>`，是包含这份 SKILL.md 的目录。在项目根目录跑，
这样工作文件会落在根目录的 `.taste-skill/` 里。
脚本要 Node 22 或更高，还要已经装好的 Chrome、Edge 或 Chromium。
脚本什么都不安装。`assets.mjs` 另外要能上网。它不用 API 密钥。

## 页面，还是应用屏幕

先定这是两种活里的哪一种。

- **页面**是用来读、用来滚的：落地页（landing page）、营销站或产品站、
  作品集（portfolio）、活动、餐厅、单页（one-pager）。走下面的**流程**。
- **应用屏幕**是用来干活的：仪表盘（dashboard）、后台或数据分析视图、设置、账单、
  要一件件处理的收件箱或队列、钱包、带筛选的列表、编辑器或搭建器。
  走 **`references/app-screens.md`**。这份参考仍是英文，整份读完再动手。
  它有自己的流程，自己的发牌（`draw.mjs --app`），
  自己的本家规矩（那里安静的边框、小标签、重复的面板是正常的；渐变、发光、色块方框里的图标、
  彩虹图表、编出来充门面的数字不是），还要跑 `inspect.mjs --app`。
  开工前把那个文件整份读完。下面这套页面流程用不上。

展示自己应用的产品站，仍算页面。上面那些界面碎片，内部按应用屏幕的规矩做。
这个产品的应用风格只发一次牌，放进它自己的文件夹，页面的颜色和字体留着：

```bash
node <skill>/scripts/draw.mjs --app --kind <kind> --brief "<the product>" --keep palette,type --out .taste-skill/app
```

页面上露出的每一块碎片都做成这个应用的真零件：首屏里能操作的那块屏幕、某个功能的裁切、
一张图表。面板、表格、控件用 `assets/app.css`。
图表用 `assets/charts.js`。数据要对得上。只说清一个发现。
按这页蓝图对待图片的方式去裁、去缩放。一块看起来像能用的产品的碎片，是软件页面最强的图。
灰条和占位数字是最弱的。一个请求里两种都有（落地页，加上它后面的仪表盘）时，各走各的流程，
共用一套配色、一套字体。

## 流程

按顺序做。第 1 到 5 步只要几分钟，但这几步决定这页好不好。

### 1. 读简报，读项目

先弄清什么是真的：题材、观众、这页必须让人做的那一件事、技术栈、
已有的品牌（颜色、字体、标志）。最要紧的是**到底有哪些图**：项目自己的照片或产品图、
能拿出来看的真界面、你能调用的生图工具，或者什么都没有。不要围着你没有的图来计划。自己没有，
很少等于什么都没有。题材的城市、街道、材料和历史都在公开档案和博物馆里，
注明出处就能用（第 6 步，`scripts/assets.mjs`）。

请求含糊时，自己定，用一行写出你的读法，别先问。只有缺的事实会卡住活时才问（比如没有产品名）。

然后在笔记里**把题材盘点一遍**：八到十二件只属于这个客户、不属于对手的东西。看这些：

- 它的名字，以及名字是什么意思。
- 地址、门牌、街道、街区，那个地方长什么样（瓷砖、招牌、漆色、店招上的字体、光线、天气）。
- 简报里的数字（座位数、房间数、到海边几分钟、价格、年份）。
- 它活在什么限制里（一个月只做一批、冬天关门、要预约）。
- 材料和颜色。
- 仪式和钟点（五点点火炉、七点的渡船）。
- 它那个世界里印出来的东西（时刻表、标签、票、招牌）。

第 4 步的点子从这份清单来。盲测里，每份简报赢的那页，
都是从这样一份清单上的某一条做出来的（客户的名字和它的意思、它站着的那条街、让它成为它的那一条限制）。
输的那些页，构图不错，点子却是品类的。这份清单也是你的搜图词：上面每个地方、每种材料、
每件印刷品，都是第 6 步的一条查询。

### 2. 先写论点

动手设计之前，把页面写成一条条说法，每条配上证据，一个区块一行，
照 `references/copy.md` 第 1 节那样。说法决定有哪些区块、
按什么顺序排。没有说法的区块删掉。这样才能避开那套库存顺序：首屏、客户标志、三个功能、证言、
价格、行动号召（call to action）。

### 3. 发方向

```bash
node <skill>/scripts/draw.mjs --sector <sector> --brief "<one line about the subject>" \
  --sections <roles in the order of your argument> [--tone <tone>] [--have <assets>] [--keep palette,type] \
  --options 3
```

这会发出三个方向，每个打一段短摘要。
拿每一个对着你的清单比：哪种构图能托住只有这个客户才有的东西？挑那个，别挑最熟的。
在笔记里写一行，为什么是它。测试里，随便一个跟题材不合的方向，是页面发虚最常见的原因。
然后把整张单发出来：

```bash
node <skill>/scripts/draw.mjs <the same arguments, without --options> --direction <chosen id>
```

- `--sector`：先跑
  `node <skill>/scripts/draw.mjs --list sectors`。
  挑最接近的。
- `--sections`：角色从 `--list roles` 里来。写进命令时用这些原文，
  不要译：`features`（功能）、`showcase`（展示）、
  `how-it-works`（怎么做）、`testimonial`（证言）、
  `proof`（证据）、`stats`（数字）、`pricing`（价格）、
  `faq`（问答）、`cta`（行动）、`footer`（页脚）、`intro`（引入）、
  `about`（关于）、`work`（作品）、`gallery`（图集）、
  `list`（列表）、`contact`（联系）。首屏不用写，它默认带着。
- `--tone`（可选）：只有简报明确要某一种时才传。传这些原文：`quiet`（安静）、
  `bold`（大胆）、`warm`（暖）、`technical`（偏技术）、
  `playful`（活泼）、`luxury`（奢）、`editorial`（编辑腔）。
- `--have`：真有的素材，逗号分开。
  `photography`（项目自己拍的地方、人或作品）、
  `product-photo`（这件产品的照片，或能做出这种照片的生图工具）、
  `product-ui`（真截图）、`illustration`、`video`。
  一样都没有就别写这个参数。发牌就会避开靠这些素材的构图，
  方向单会说怎么老实地填图位（软件就展示用 HTML 搭出来的自己的界面；
  没有照片的产品就画出来，放进它那个世界的真图里，绝不做一张假的产品图）。
  你将在公开馆藏里找到的图，不是项目自己的。别写进 `--have`。
- `--keep palette,type`：品牌已经定死颜色或字体时用。发牌就只发构图。
  你把品牌的具体值填进各个角色。

命令会打出一张**方向单（direction sheet）**。
这就是这次要做的美术方向（art direction）。

- **照单采用。** 别跟你本来就会做的版式掺在一起。觉得生，那就对了。熟的那套版式，
  正是这份技能要挡住的。
- 重发一个槽位（`--redraw hero | type | palette | photos | scenes | section:<role> | direction`），
  只在你能说清理由时：它顶着已经写明的品牌限制，或者它要一件不存在的素材。绝不为了更顺手而重发。
  每次重发都写进报告。
- 发出的区块装不下真内容时（它要对比三档方案，其实只有一个价格；它要五句引言，一句都没有），
  别把内容掰弯去迁就版式。用 `--alternatives <role>` 把别的列出来，
  挑假设和内容对得上的那个，
  用 `--redraw section:<role>=<id>` 换上。
- **拿配色对一下题材。** 发出的配色既是一组颜色，也是一组比例：一块底色（ground）、
  一块墨色（ink）、一块强调色（accent）、若干色块（field）。
  颜色要是跟题材自己的材料打架（泥煤威士忌配上糖果似的粉彩，山间小屋配上霓虹），
  就把配色重发一次。题材要是有一眼就认得出的自己的颜色（它的材料、街上的漆、窗外的风景），
  比例留着发出的那套，颜色改从题材上取，并在报告里写明。
- 随时用 `node <skill>/scripts/draw.mjs --show`
  再打一次。长会话里，每做一个区块之前重读一遍。

### 4. 找点子

方向是一种构图办法。点子是让这页只属于这个题材、不属于别的。在笔记里写下这句话。
两个空都从题材本身填上之前，不要开工：

> 在这页上，**[属于这个题材的某样东西]** 变成 **[方向要的那个装置]**。

第一个空往这些地方找：

- **它产出什么。** 这东西做出来的是什么？把真产出放到页面上当材料。
  （一台会印诗的相机，把文案做成一张张纸条交了出去。）
- **它的物件或外形。** 实物长什么样，剖面、剪影呢？放大它，裁它，让它当框，
  或当唯一的母题（motif）。
- **它的名字。** 这些字母能不能托住一张照片、叠成一堵墙、拆开站到两个角上？
- **它的地方。** 有没有一个景，让人想去那儿？
- **它的仪式。** 有没有一套顺序，页面滚动时可以演出来？
- **它已有的印刷物。** 它的世界里已经印着什么：票、菜单、标签、收据、请柬、文件夹、手册？
- **它的反面。** 别的哪个品类占着它自己没有的那种感觉？

第一个空从你的清单（第 1 步）里填，别从品类里填。
**竞争对手测试：**
把最近的真对手放进这句话（两条街外的那家面包店、另一家橡木家具匠、同一座山上的另一间小屋）。
这句话还成立，点子就属于品类。一条面包是每家面包店的。这条街的七扇门，只有这家用它们当名字。
「干净、现代」不是点子。研究小组打分最低的那些站，点子栏写的是「标准公式之外，没有」。

**一个能动手的东西。** 给页面一件访客能做的事，或每次来都不一样的事，
从点子里做出来：选一种木头，看这把椅子换成那种木头；打上你的名字，看它用铸字厂的字母刻出来；
把贷款额定好，读出真的每月还多少；看小屋的炉子现在着没着，末班渡船还有多久；选一个尺寸，
拿它对着房间看。盲测里，赢的每一页都有这么一件，评审第一个点名的就是它。规矩：用题材的真内容；
手机上拇指就能用；没有脚本时有一个朴素的能用的版本；绝不挡住人读；就一件，不是一堆玩具。
它在第 6 步里作为页面的一部分做出来，不是留到第 9 步当动效补上去。

**场景也要扛点子。** 方向单上的滚动场景（scroll scene）是等着题材来用的装置。
开工前从清单里定每个场景演什么：穿行镜头（fly-through）穿过的是这家工作室自己的片头卡，
那条路线是这批货真走的路，铺满整屏打开的那张图是客人醒来会看见的房间。
一个场景塞满谁的都行的图，就是屏保。

### 5. 写文字

写标记之前，整页先写成一份文案稿（copy deck，纯文本），
照 `references/copy.md`：

- **每条大标题在每个宽度上都是两行或更少。** 定下一句之前，
  先按 copy.md 第 2 节算一遍。字号够有把握时，大约 32 个字符到哪个宽度都安全。
  研究过的那些展馆站，首屏标题的中位数是 5 个词、32 个字符。
- 一句支撑句，直接放在大标题下面（距它 32–48px），和它一起出现。绝不丢在首屏最底下，
  也不被动画扣住不放。大标题是一个名字，或是一种说法时，这一句就直说这东西是什么。一个主要动作，
  按钮上的字写它真正做的事，作为真按钮放在首屏上。
- **首屏用大字回答访客的第一个问题。** 活动：是什么、什么时候、
  在哪儿（日期要进大标题，或用第二档字号，绝不能只剩小字）。产品：是什么、多少钱，或做什么。
  人：是谁、做什么。人是冲着来的每一块（阵容、菜单、房间、价格）都有自己的标题，
  导航里也有自己的位置。
- **把内容写全。** 简报要的每个区块，信息都交完整：整份菜单带价格，每间房有自己的细节，
  每个讲者和每场演讲，价格写明包含什么，每个真问题都有答案。区块太瘦，
  是干净的页面输给更挤的页面最常见的原因。
- 简报没写到的地方，要用样例细节补上（菜名、房名和房价、项目标题），
  这样设计才能在摆满的状态下被看见。在报告里列出来，等客户确认。证据一律不编：没有客户、引言、
  评价、媒体、标志或经营数字，就不要写。

### 6. 先做成静的

做的时候，心里先把动效关掉。一页要靠动画才像做完了，那它就没做完。干活顺序：

1. **变量（token）。** 方向单上的颜色角色和字体角色，写成 CSS 自定义属性。
   后面所有东西只许引用这些变量。
   `<skill>/assets/base.css` 是一套中性底子，
   你可以从它开始（重置、变量名、随宽度变的字号阶梯、网格、焦点和选中样式、动效辅助）。
   它自己没有长相。
2. **首屏，严格按蓝图写的那样做，** 桌面宽度和手机宽度都做。别的还没出现之前，
   先把该大的做大，该小的做小。
3. **每个区块按它的蓝图做，** 装上这个项目的内容。几何留着，题材换掉。
   挨着的区块不能长成同一个版式。**把点子带进每一个区块，** 价格、常见问题、页脚也算。
   研究里最常见的失败，好站点也不例外，是首屏很特别，后面全是库存块。
4. **图，** 按这个优先顺序：
   1. 项目自己的。
   2. 你有生图工具的话，生成的。
   3. **题材那个世界的真图，从公开馆藏里来，** 只要存在一张诚实的。
      用 `node <skill>/scripts/assets.mjs "<query>"`
      搜（Openverse、维基共享 Wikimedia Commons、
      芝加哥艺术博物馆 Art Institute of Chicago、
      大都会艺术博物馆 the Met。默认只要允许商用的许可）。按清单搜，
      别按品类搜：老明信片上的那条街、这一带的旧地图、材料的近看、版画里的这门行当、
      同类的博物馆物件、一张植物图版、一张星图。用得大，而且是有意这么用：一张档案照片当首屏，
      一幅版画放大成这页的母题，这条街的真地图当成联系区块。选定之前，每一张都要先看。
      `--get <ref>` 把它下到 `assets/`，并记下来源和许可。
      `--credits` 打出页脚用的署名行。找到的图是客户周围的世界，
      绝不能说成客户自己的产品、房间、菜、某个人或团队。
   4. **用代码照着题材本身画，** 画那些没有诚实照片的东西（它的物件、瓷砖、窗子、产品界面）。
      用配色里的真颜色，画成一套一致的扁平图形。
   5. 方向单上发到的照片，只在一张老实的通用图说得通时才用（海边的房子就用海），绝不要拿来顶替题材。
   6. 只剩字和颜色。

   项目有自己的影像，或有工艺、产品的真图时，首屏就把它放出来，放得大（大约占屏幕四成，或更多）。
   绝不要在页面上写一句图从哪来、或者图不是什么（「这些都不是我们的吧台」）。图说写这张图是什么。
   署名用小字放在页脚。作品是为这份简报编出来的作品集，
   每一件都画成那件作品的一张完成静帧（带自己字体的片头卡、一帧结束画面、一张海报），要有真细节，
   绝不要画成客户产品的一个小符号。

   **检查器要卡的底线：** 页面上至少四张真图，
   通常六到十二张（照片、档案图、地图、版画、影像、位图。软件的话，裁过的界面碎片也算）。
   SVG 画的不算进这条底线。没有照片的才画，真图还是要带着。只要有一段老实的片子，
   就加一段会动的图：用 `assets.mjs --video "<query>"` 搜，
   做成静音循环，带一张海报帧（poster）。模型会跳过图和影像，因为找它们费事。
   没有它们，这页就失败。

   `references/imagery.md` 写了怎么搜、许可和署名、视频、
   绘制、裁切和处理。
5. **第 4 步那个能动手的东西，**
   做进那个能证明这条说法的区块里（常常是首屏，或预订那一块）。用真内容，做一个给拇指用的手机版，
   再留一个朴素的退路。
6. **滚动场景，** 方向单发了它们的时候（方向单第 9 节），
   每一个都带着它要承托的那个区块：页面上的大时刻、穿过作品飞过去的镜头、铺开到整屏的那张图、
   滚动时被压弯的那个词。
   从 `<skill>/assets/scenes/` 把共用舞台和这个场景的文件拷过来，
   用这个项目自己的图和字填进去，设上页面的变量，让它跟上这页的样子。场景就是构图：页面有多长、
   每一屏给什么，都由它定。所以现在就做，每一轮看的时候都要看见，不要拖到最后再贴上去。
   `references/scenes.md` 说怎么把一个场景放到页面上、怎么填、怎么适配、
   怎么检查。`assets/scenes/demo/<id>.html` 是每一种都能跑的例子。
7. **要满。** 每一屏桌面都当海报看：一件压得住的东西，加上它带着的内容。一屏大半是空底，
   那是区块没做够，不是留白休息。一页故意的休息最多一次。近乎空的屏幕有两屏或更多，检查器判失败。
   正文用满墨色，16px 或更大。灰色只给旁边的小注。
8. **框。** 页面在每个宽度上都有一对相等的外页边。
   每个区块都用上页面已经定好的那一档宽度：字在左半边时，右半边放它的图、第二栏、列表或一个数，
   绝不空着。不对称只许出现在网格里面，不许出现在框上。一块空，只有对面有东西把它封住时才放。
   页面上没有一段比大约半屏还高、却什么都没有的地方。桌面上，区块和区块隔 120–240px。
   人是冲着来的每个区块，开头都有一个标题，标题就叫它的名字。首屏用一个 `h1` 放这页的标题。
   一页看起来不对时，读者最先点名的就是这些（「没有清楚的标题」「空得没道理」「全挤到一边」）。
   检查器会逐条量。
9. **状态和语义。** 真的链接和按钮，看得见的焦点，替代文本（alt），
   手机版是单独的一种构图。

要一个决定背后的细节时，读 `references/type.md`、
`references/colour.md` 和
`references/layout.md`。下面这些规矩是短的那一版。

### 7. 过关

```bash
node <skill>/scripts/lint.mjs <source files or folder>
node <skill>/scripts/inspect.mjs <url or path/to/index.html>
node <skill>/scripts/scenes.mjs <url or path/to/index.html>     # when the page has scroll scenes
```

`scenes.mjs` 给每个滚动场景拍照，拍它停留区间（hold）的 0、10……100%，
桌面和手机都拍，也拍减弱动效的那一页。方向单上有场景时，`inspect.mjs` 还会把整段滚动拍成一串画面（`desktop-film-NN.jpg`）。
一个场景从没开始，或在桌面上停着不动，就是 `FAIL`。

`lint.mjs` 扫描源码，找禁用写法和库存套话。
`inspect.mjs` 在真浏览器里打开页面，宽度 1440、768、390 像素，
然后量它：大标题有几行、字号、真正加载上的字体、颜色、线、阴影、渐变、对比度、溢出，
还有框（左右页边等不等、区块是不是挤在一边、有没有空白段、标题在不在、有没有没标题的区块、
文字有没有贴着屏幕边）。截图存到 `.taste-skill/inspect/`。
每个 `FAIL` 都修。每个 `WARN` 都当成错的，除非你能用一句话跟设计师说得通。
重跑，直到没有 `FAIL`。别跟量出来的数争。也别把东西藏起来，不让它量到。
检查器用一个用完即扔的本地服务器来打开本地文件。页面如果还得能直接从文件系统打开，
结束前就用那种方式打开一次 `index.html`。

### 8. 看

过关只说明没量到禁掉的东西。不说明这页好。
打开检查器列出的截图（每个视口都开，用你的看图工具，或 Read 工具），
按 `references/critique.md` 来评：十四遍看、
按 Awwwards 加权的分数、各项封顶。按它规定的格式把点评写下来，修最严重的三个问题，
再跑检查器，再看。最多三轮。

只看图来判。截图里看得见，问题就是真的，代码怎么写不管。

### 9. 动起来

现在做动效这一层。这是必须的，而且不只是一次淡入。检查器会数页面在加载和滚动时真的在动的元素。
少于八个就失败（少于十六个就警告）。滚动场景如果有，第 6 步已经做好了。围着它们，
这一层有四部分：

1. **招牌动作（signature move），** 方向单上点名的那一个，做好。
   发出的场景可以就是它。
2. **每个区块的各部分都有入场：** 先标题，再文字，再图。错开 60–90 毫秒，
   连着透明度往上移 16–32px。区块进入时触发一次。不是整块一起淡入。脚本要是挂了，
   内容绝不能还藏着出不来。
3. **每个控件都有反馈：** 按钮、链接、卡片，还有那个能动手的东西。按下、悬停、聚焦，都要有。
4. **一段在动的图：** 找到的片子做成静音循环，或照片上缓慢缩放、缓慢漂移，
   或首屏的图跟着滚动动。

只动变换（transform）和透明度（opacity）。
每个动作都要有 `prefers-reduced-motion` 的退路：内容留着，路程拿掉。
一个动作要改掉整屏的颜色或版式（一章一章换颜色、一段钉在屏幕上的故事），那就是构图的一部分，
所以在第 6 步就做，每一轮看都要看见。
`references/motion.md` 里有变量，也有测过的做法。然后再跑一次检查器。
每张截图都查，有没有内容没出来。

### 10. 报告

下面每一条都成立，再去报告。测试里，下面每条被跳过的那次，结果都不好：

- 最终版页面上，`inspect.mjs` 在 1440、768、390 都显示 **0 FAIL**。
- 最后一次改完之后，它列出的每张截图你都打开过，不只是首屏。
- 有滚动场景时：`scenes.mjs` 在最终页上跑过，没有问题。
  每一张表你都读了（桌面、手机、减弱动效）。
- 一个陌生人看首屏五秒，能说出这是什么、该做什么。
- 每个区块都有标题。两边页边对得上。页面上没有一段是空的。
- 最后一轮点评，按 `references/critique.md` 第 4 节的样子写下来了。

简短告诉用户这些：发出的方向（名字，和种子 seed），以及每次重发和理由；点子那句话，
和那个能动手的东西；最后一轮点评的分数，以及还差在哪；每一张找到的图、每一段片子，写上标题、
作者、许可和来源页（`assets.mjs --credits` 会打出这份清单），
以及署名放在页面的哪里；哪些是随库附带的照片、哪些绘制在代替摄影（好让人换掉）；
上线前必须换掉的样例内容。没跑的检查，别说跑过。

## 本家规矩

每次都守，不管发到哪个方向。`inspect.mjs` 会量它们。

| 规矩 | 改成这样 |
| --- | --- |
| **大标题：每个宽度上都是两行或更少。** 每个 `h1`–`h6`，以及首屏的主句，不管它用什么标签。 | 先砍字。再把行宽（measure）加宽。最后才动字号。 |
| **首屏有一个清楚的标题**，放在全页唯一的 `h1` 里。每个区块也有标题。 | 说这是什么：名字加上它干什么，产品加上它是给什么用的，活动加上日期和地点。 |
| **外页边相等。区块不要挤在一边**，屏幕另一半空着。 | 每块空都用对面的东西封上：这个区块的图、第二栏、列表、一个数。 |
| **不要有空白段**，高过大约半屏的那种。 | 用正常的区块间距。故意的休息是摆好位置的一张图，或一片颜色，一页一次。 |
| **陈述是段落。** 放大的引入句或引语，标记成 `<p>` 或 `<blockquote>`，停在陈述的字号（桌面 36px 或更小，手机 24px），大约 25 个词、三行。 | 比这更大，它就是大标题，两行的规矩套上去。盲测里，评审把一句 42px、排了四行的话，读成四行的大标题。 |
| **不要眉标（eyebrow）。** 标题上面不要再放一行小标签，大标题上面不要胶囊徽章（pill badge），不要 "New ·" 那种小芯片（chip）。 | 信息放进标题或第一句，或者丢掉。 |
| **真代码块以外，不要等宽字体（monospace）。** | 用正文字体。数字要排齐时，用表格数字（tabular figures）。 |
| **不要序号。** 不要 01 / 02 / 03，不要 (001)，不要 "Step 2"。 | 顺序靠位置、大小，或靠字本身看出来。顺序真的要紧，用真的 `<ol>`。 |
| **不要细线。** 不要发丝那么细的分割线（hairline），不要 1px 描边的盒子，不要网格线、十字线或裁切角标。 | 用空。背景色调差一档。换一个大小。一块填实的形状。 |
| **不要渐变（gradient）。** 不当背景，不上按钮，不进文字。 | 平的颜色，或一张真照片。照片上、文字底下垫一层中性遮罩（scrim），这是唯一的例外。 |
| **停着的东西不要阴影。** 不要发光。 | 表面之间靠色调差一档。阴影只给真浮起来的：菜单、对话框。 |
| **不要助手默认那套配色。** 不要黄奶油的底配赤陶色或锈色。不要紫罗兰，不要靛蓝。 | 用发出的那套配色。 |
| **不要又小又全大写、字距拉开的标签。** | 用正常句子的写法，字号要能读（sentence case）。 |
| **不要头顶一个图标的功能卡片，不要一排长得一样的卡片。** | 用发出的区块蓝图。 |
| **不要玻璃效果（glass）。** 不要背后模糊的面板（backdrop blur），不要浮着的胶囊导航。 | 一条朴素的栏：文字标志（wordmark）、几个链接、一个动作。 |
| **不要表情符号，不要渐变团，不要装饰形状，不要用灰条假装的仪表盘。** | 一张真图，一块真的界面碎片，或者什么都不放。 |
| **大标题里不要单把一个词打扮一下**（斜体、衬线、变色、下划线）。 | 一种字体，一种颜色。强调靠词，不靠打扮。 |
| **字体最多两种，** 通常一种。 | 用发出的字体系统。 |

三处保留自己的惯例，检查器不碰：`<pre>`/`<code>` 里的真代码（那里用等宽字体是对的），
真表格和表单字段（可以有线），以及根上带属性 `data-ui` 的真界面碎片（产品自己的边框和菜单。
见 `references/imagery.md` 第 7 节）。

说老实话，为什么是这些。有些是研究量出来的。247 个站里，小组打到 7.5 或更高的，
用图标功能卡片的比例是 1%，打到 6.5 以下的站是 28%。
胶囊徽章是 14% 对 34%。渐变是 22% 对 52%。阴影是 24% 对 48%。
又小又拉开字距的大写是 16% 对 57%。另一些是主人的口味，
逆着现在展馆里的时髦：等宽小标签、序号、发丝网格，在获奖站上其实*更*常见，比弱的站更常见。
生成器才会去学它们，所以它们现在看起来像戏服。这里禁，没有例外。
`references/tells.md` 记着这份标明时期的俗套名册。

装饰拿掉，空就出来了。绝不要再拿另一种装饰填回去。用尺度填（把主要的东西做大），
用写全的内容填，用为这个题材做的一张图填，或者用一片平涂的颜色填。故意空着，一页最多一次。

## 手艺上的规矩

短的一版。数字来自那项研究，除非标明是本家风格。

**字体（type）**

- 看得见的活，两种或三种字号就够：一个很大，一个很小，中间不插一档。研究过的站点，
  标题对正文的比例，中位数是 4.3。
  最好的那些远远超过这个（最大的字：顶尖站中位数 8.4vw，弱的站 5.0vw）。
- 展示大字（display type）：字距（tracking）-0.02 到 -0.05em，
  行距（leading）0.85–1.05。正文：16–20px，行距 1.45–1.6，
  每行 45–75 个字符。
- 一页五种字号，到顶了。一个字体家族是常态（研究过的站里，三分之一是这样）。两种是上限。
- 默认靠左。居中最多一个瞬间。

**空间**

- 一套网格，一对收紧的页边（16–32px），到处都用。大的东西一直铺到边上。整页的文字块，
  左边只对齐到两条或三条线上。
- 不对称在网格里面，绝不在框上。两条外页边相等。标题不在正中时，网格远处要有东西应它。
- 区块和区块的间距，要明显大于一个区块内部的任何间距：桌面 120–240px（研究的中位数大约是 240）。
- 每个区块的构图都和挨着它的不同。哪个都不是卡片格子。

**颜色**

- 一块底色，一块墨色，一块强调色。强调色用在那个动作上，最多再给另一处。
- 正文用满墨色。整页用浅灰来排，看着像没做完。
- 表面靠色调小幅差一档分开，绝不靠一条线，也绝不靠一块阴影。
- 一个区块可以换掉整片底色。没有东西是渐隐进别的东西里的。

**图像**

- 一张压得住的图，胜过六张小图。高分站上，首屏的图或影像盖住至少半个首屏，这种情况占 68%。
- 裁切比例一样，处理一样，方角，除非方向单另说（研究过的站里，73% 让图保持方角）。
- 没有图，好过占位图、一个图标，或一块抽象形。为这个题材画的图，用它的颜色、画得仔细，
  比「没有图」和「占位」都好。找到的、署了名的、它那个世界的真图，还要更好。
- 每张找到的图都下到项目里，在页面上署名，在报告里列出来。一张都不许说成是客户自己的。
- 任何东西都不许压在大标题或一句陈述上（检查器会判失败）。

**组件**

- 按钮：平的，只填一种颜色，要么方角，要么全圆，
  全站定一次（顶尖站：52% 方角，23% 胶囊。9–16px 那种「柔和」圆角，是弱站的默认）。
  强的首屏大多没有按钮，或者只有一个。
- 导航：文字标志，三到五个朴素链接，一个动作。这条栏不要再加一层装饰。
- 页脚是设计过的收尾，不是一张站点地图。大多数强的站上，名字会拉满整宽，再出现一次。

## 特殊情况

**已有品牌，或已有设计系统。** 传 `--keep palette,type`，
把品牌的颜色和字体填进各个角色，发牌只取构图。本家规矩仍然生效。
品牌自己非要一件被禁的东西（标志放在渐变上，强调色是紫罗兰），就留着这份品牌素材，报告里写明，
检查器只对这一条传 `--allow <rule>`。

**改版、换样式，或审查已经有的页面、应用屏幕。**

1. **记下改之前的样子。** 项目按现在的样子跑，
   检查进它自己的文件夹（`inspect.mjs <url> --out .taste-skill/before`，
   应用屏幕加上 `--app`），并用 lint 扫它的源码。读代码：用的什么框架，
   样式怎么写的（Tailwind v3 或 v4、CSS modules、
   styled-components、普通 CSS），有哪些组件，
   什么必须留住（路由、表单、数据、行为、品牌自己的素材）。
2. **只做审查的话，到这里就停。** 用 `references/critique.md`
   点评改之前的截图，把发现和检查器量到的数一起列出来，点出最能把这页推一把的三个改动。
3. **留着技术栈、内容，以及已经能用的部分。** 不换框架，也不换样式库。要加任何东西，
   先看依赖文件。换样式：版式留着，字体、颜色、
   组件从发出的方向里拿（品牌定死的，用 `--keep` 留住）。改版：发一整套方向，
   在现有组件里面，按蓝图把区块重做。两种都从流程的第 2 步往下走，用这页的真内容。
4. **干活顺序，成效大、风险小的先做：** 字体（用哪套、放到多大），
   颜色（一块底色、一块墨色、一块强调色），
   框（页边、区块的节奏、首屏一个标题、每个区块一个标题），状态（悬停、聚焦、加载中、空、出错），
   然后把库存组件换掉（图标卡片、胶囊徽章、渐变团、卡片格子），换成发出的蓝图。
5. **拿出证明。** 再检查一次，输出到 `.taste-skill/after`。
   每个宽度都比改前和改后。以前能点的每个链接、表单、菜单，都再点一遍。
   改前和改后的测量，并排写进报告。

**一个组件，或单独一个区块，不是整页。** 有方向可跟，就不要发牌。没有方向，才发。
跟上周围的设计。本家规矩和手艺规矩都用上。做完仍然要检查。

**没有结账，也没有表单的后端。** 简报写了真的去处，主要按钮就去那儿。
不然就打开一封写好主题和正文的邮件（`mailto:`，把访客选的填进去）。
商店就指向 `#checkout`，报告里写明：上线前必须接上。绝不做一张假的付款表单。

**没有 Chrome，或没有 Node 22。** 跑
`lint.mjs`（要 Node 18 或更高），用你手头任何浏览器工具截图，再点评这些图。
报告里写明：检查器没能跑。

**没有网络。** `assets.mjs` 哪个来源都到不了，就把图画出来，
报告里写明：公开馆藏没能搜。
