# 最坏情况清单

> （本文件是 `break-ui` 的参考文件，翻译自 Emil Kowalski 的仓库 https://github.com/emilkowalski/skills 的 `skills/break-ui/CATALOG.md`，许可证 MIT，仅供自用。“值”一栏里的示例数据保持原样。）

会搞坏界面的真实值，按组件显示的值的种类分组。用和你第 1 阶段表格里字段对得上的那些行。每个值都是真实用户可能产生的；右边的说明写的是它常常会搞坏什么。

邮箱和网址用 `example.com`、`example.org` 或 `.test` 域名，这样测试数据永远不会指向真实的邮箱或网站。

## 邮箱、网址、标识符

没法断行的字符串：它们没有空格，所以浏览器找不到地方换行。

| 值 | 会搞坏 |
| --- | --- |
| `bartholomew.fitzgerald@northwind-industries-holdings.example.com` | 经典案例。没有 `overflow-wrap: anywhere` 时，会把同一行的其他元素全部挤出去 |
| `a@b.co` | 最短的真实邮箱；按长邮箱设计的布局会显得空荡荡 |
| `first.last+billing-notifications@example.com` | 带加号的地址；校验会拒绝 `+`，显示时截掉了有意义的部分 |
| `ops@sub.department.region.example.co.uk` | 很多层子域名、两段式顶级域名；影响“提取域名”的逻辑 |
| `https://example.com/workspaces/acme/projects/q3-launch/docs/9f8e7d6c5b4a?tab=comments&filter=unresolved` | 长网址；溢出，而且末尾截断会藏起真正有区别的部分 |
| `9f8e7d6c-5b4a-4c3d-8e2f-1a0b9c8d7e6f` | UUID；等宽字体的宽度，适合在中间截断 |
| `Q3 Board Deck — FINAL (revised) v12 [approved by legal].pdf` | 文件名；末尾截断会藏起版本号和扩展名，路径里有括号和破折号 |
| `IMG_20250914_183022_HDR_portrait_edited_edited.HEIC` | 相机生成的文件名；没法断行，扩展名是大写 |
| `@a` / `@thisisaverylongusernamethatisallowed` | 用户名的两个极端 |

## 来自数据的标签、标题和文案

| 值 | 会搞坏 |
| --- | --- |
| `Senior Product Design Engineer, Platform Infrastructure` | 很长的职位名；在次要位置折成三行 |
| `Invitation expired 12 days ago` | 很长的状态徽标；徽标折行，或者把名字那一列挤窄 |
| `Benachrichtigungseinstellungen` | 德语复合词（30 个字符，没有空格）；标签溢出，没法断行 |
| `Paramètres de confidentialité et de sécurité` | “Privacy & security” 翻成法语后变长；界面文案翻译后通常长约 30% |
| 一项上有十二个标签：`design`、`frontend`、`q3`、`urgent`、`needs-review`…… | 标签行折成一堵墙；需要一个 `+8` 这样的“还有更多” |
| 一个叫 `customer-feedback-from-enterprise-onboarding` 的标签 | 单个标签比容器还宽 |
| `Untitled` / 空字符串 / `   ` | 标题缺失；标题塌掉，行高变成零 |
| `<script>alert(1)</script>` / `&amp;` / `**bold**` | 转义问题；必须原样显示成文字 |
| `Line one` + 换行 + `Line two` | 单行字段里有换行；行高翻倍，或者换行被悄悄吞掉 |
| 一段粘贴进来的 2,000 字符的描述 | 行数限制、“显示更多”和文本框自动变高 |

## 数字和金额

| 值 | 会搞坏 |
| --- | --- |
| `0` | 零状态：“0 members”、空的进度条、算百分比时除以零 |
| `1` | 单复数：“1 members”、“1 days ago” |
| `1284` | 需要千位分隔符：`1,284` |
| `1000000` | 数量徽标的宽度；在不需要精确的地方考虑用紧凑写法 `1M` |
| 金额 `12345678.9` | `$12,345,678.90`；撑爆合计那一列 |
| `-42.5` | 负号、标红的逻辑、会计格式里的括号 |
| `0.1 + 0.2` | 直接显示出 `0.30000000000000004` |
| `142%` / `-3%` | 进度条和仪表超出范围 |
| `null` / `undefined` / `NaN` | 被原样显示出来 |
| `de-DE` 下的 `1.284` 和 `en-US` 下的 `1,284` | 地区格式；写死的分隔符对世界上一半的人都是错的 |
| 实时变化的值（`99` → `100`） | 没有 `tabular-nums` 时宽度跳动、抖动 |

## 集合

| 值 | 会搞坏 |
| --- | --- |
| 0 项 | 空状态，以及到底有没有做空状态 |
| 1 项 | 只有一张卡片时看起来像坏了的网格；“1 of 1” |
| 刚好一页的数量，以及一页 + 1 | “Showing 40 of 40” 里的差一错误，分页显示出一个空的第 2 页 |
| 1,000 项以上，不分页 | 滚动性能、渲染时间、内存；还有 “Showing 40 of 1,284” 的文案 |
| 有一项比其他项大 10 倍 | 瀑布流和网格的行被拉到和最高的那项一样高 |
| 名字完全相同的几项 | 名字是唯一区分字段的列表 |

## 时间

| 值 | 会搞坏 |
| --- | --- |
| 现在 | 显示“0 seconds ago”，而不是“刚刚” |
| 12 天前、11 个月前、3 年前 | 相对时间的分界点；大约一周后应该改成显示具体日期 |
| 未来的日期 | “in 3 days” 和 “-3 days ago” |
| `1970-01-01` | 一个为零的时间戳被当成真实日期显示 |
| `2025-12-31T23:30:00-08:00` | 在 UTC 和用户所在时区里显示成不同的日期 |
| 很长的时长（`1,284 hours`） | 时长格式从不进位成“天” |

用 `Intl.RelativeTimeFormat` 和 `Intl.DateTimeFormat`，不要手动拼字符串。

## 图片和媒体

| 值 | 会搞坏 |
| --- | --- |
| 返回 404 的头像网址 | 显示破图图标，而不是退回显示首字母 |
| 完全没有头像 | 备用方案本身：首字母、颜色、和真实头像大小一致 |
| 4000×200 的全景图当头像或封面 | 没有 `object-fit: cover` 时变形 |
| 200×4000 的竖长图 | 同上，换了个方向；还可能把卡片高度撑爆 |
| 透明 PNG 标志、深色模式下的深色标志 | 在背景上看不见 |
| 加载很慢的图片 | 没有固定尺寸或 `aspect-ratio` 时布局跳动 |

## 状态

| 值 | 会搞坏 |
| --- | --- |
| 加载中 | 骨架屏和最终布局对不上，加载圈把内容挤动 |
| API 返回错误 | 没有错误状态，或者显示原始错误信息（`TypeError: Cannot read properties of undefined`） |
| 部分数据 | 同一个列表里有的可选字段填了、有的没填；各行对不齐 |
| 所有状态同时出现 | 一个列表里出现所有枚举值（`active`、`invited`、`expired`、`suspended`）；徽标宽度各不相同 |
| 没有权限 | 操作被禁用；这一行的布局还一样吗？ |
| 列表里有当前用户自己 | “你”的标签，不应该对自己生效的操作 |

## 环境

不是数据，但用同样的方法检查：先切到最坏情况，再改变这些条件。

| 条件 | 会搞坏 |
| --- | --- |
| 容器宽 320px | 上面所有的溢出问题，一次性全部出现 |
| 放在窄侧边栏里 | 按整页宽度设计的组件，被复用到 280px 宽的一栏里 |
| 2560px 宽 | 一行太长读不下去，内容孤零零地挤在一边 |
| 浏览器缩放 200% / 大字设置 | 固定高度把变大的文字裁掉 |
| 深色模式 | 写死的颜色，看不见的边框和标志 |
| `dir="rtl"` | 图标、箭头、内边距，以及末尾操作的顺序 |
| 触屏设备 | 只在鼠标悬停时出现的操作（悬停才出现的 •••）点不到 |
